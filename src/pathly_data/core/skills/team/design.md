# team/design

Stage 2a — Design Intelligence. Invoked by the `team` orchestrator when FSM state is DESIGNING.
Runs UI UX Pro Max design-system generation, writes `DESIGN.md`, then transitions to BUILDING.

Parse `$ARGUMENTS`: `FEATURE`, `rigor`, `autoFlow`.

## FSM operations

All events are appended to `pathly/plans/<feature>/EVENTS.jsonl` as JSON lines.
State snapshots are written to `pathly/plans/<feature>/STATE.json`.

- **Log file created:** Append `{"type": "FILE_CREATED", "file": "DESIGN.md"}`.
- **Log stage start:** Append `{"type": "STAGE_START", "stage": "DESIGNING"}`.

## Step 1 — Extract feature description

Read in order of preference:
1. `pathly/plans/<feature>/USER_STORIES.md` — use the one-line goal from the first story
2. `pathly/plans/<feature>/IMPLEMENTATION_PLAN.md` — use the first paragraph
3. Fallback: humanize the feature slug (kebab → spaces)

## Step 2 — Detect tech stack

Check in order:
- `package.json` → look for `next` → `nextjs`; `react` (without next) → `react`; `vue` → `vue`; `svelte` → `svelte`; `astro` → `astro`
- `pubspec.yaml` → `flutter`
- File extensions in `src/` → `.tsx` = `react`, `.vue` = `vue`, `.svelte` = `svelte`
- Default: `react`

## Step 3 — Run design system generation

Run: `python -c "import time; print(int(time.time()))"` and note the integer as `DESIGN_START`.

Print:
```
[DESIGNING] Generating design system for: <feature>
Stack: <stack>
Query: "<description>"
```

Run:
```bash
pathly-design "<description>" --design-system --stack <stack> -p "<feature>"
```

If `pathly-design` is not found, fall back to `python -m pathly_data.core.design.cli`.

Capture the full output. If the command fails (Python not found, script error), write a minimal `DESIGN.md` with the error noted and continue — do not block the pipeline.

## Step 4 — Write DESIGN.md

Write `pathly/plans/<feature>/DESIGN.md`:

```markdown
# Design System — <feature>

> Generated by UI UX Pro Max · Stack: <stack> · <ISO date>

## Query
<description used>

## Design System Output

<full output from search.py>

## Builder Notes

- Reference this file when implementing UI components for this feature
- Override any recommendation that conflicts with existing project design tokens
- Stack: <stack> — use stack-specific imports and patterns from the output above
```

## Step 5 — Log and transition

Append to `pathly/plans/<feature>/EVENTS.jsonl`:
```json
{"type": "FILE_CREATED", "file": "DESIGN.md"}
{"type": "STAGE_COMPLETE", "stage": "DESIGNING", "next": "BUILDING"}
```

Compute wall_seconds: run `python -c "import time; print(int(time.time()) - DESIGN_START)"`.
Append to `pathly/plans/<feature>/EVENTS.jsonl`:
```json
{"type": "AGENT_DONE", "agent": "designer", "model": "<model>", "conversation": 0, "result": "DONE", "tokens_in": 0, "tokens_out": 0, "cost_usd": 0, "tool_uses": 0, "wall_seconds": <computed>, "ts": "<iso-timestamp>"}
```

Then invoke the `record-cost` skill with:
```json
{"agent":"designer","feature":"<FEATURE>","summary":"Design system generated","conversation":0,"wall_seconds":<computed>,"total_tokens":0,"tool_uses":0,"duration_ms":0}
```

Write `pathly/plans/<feature>/STATE.json`:
```json
{"state": "DESIGNING", "artifact": "DESIGN.md", "feature": "<feature>"}
```

Print:
```
[DESIGNING] Complete. Design system written to pathly/plans/<feature>/DESIGN.md
Transitioning → BUILDING
```

## Failure handling

- If `pathly/plans/<feature>/` does not exist: print error, do not create DESIGN.md, do not transition.
- If search.py fails: write DESIGN.md with a note that generation failed, still log FILE_CREATED and transition — pipeline must not stall on a design step.
