# team/design

Stage 2a — Design Intelligence. Invoked by the `team` orchestrator when FSM state is DESIGNING.
Runs UI UX Pro Max design-system generation, writes `DESIGN.md`, then transitions to BUILDING.

Parse `$ARGUMENTS`: `FEATURE`, `rigor`, `autoFlow`.

## FSM operations

Events are logged to the central DB via `pathly_orchestrator.eventlog.append_event`.
Every event must include `"ts": "<iso-timestamp>"` using the current ISO-8601 UTC time.
State snapshots are mirrored to `<feature_path>/STATE.json` by the FSM server after each transition.

- **Log event:** `python3 -c "from pathly_orchestrator.eventlog import append_event; append_event('<feature_path>', {'type': 'FILE_CREATED', 'file': 'DESIGN.md', 'ts': '<iso-timestamp>'})"`
- **Never** append `STATE_TRANSITION` events — the FSM writes all state transitions after your AGENT_DONE.

## Role

**Stage orchestrator: Design**
You coordinate subagents, handle feedback routing, and log every phase boundary.
Logging is mandatory — each `log-phase` call is part of the pipeline contract.

> After each phase completes, log `log-phase PHASE_DONE <phase>` before starting the next.
> If `pathly-fsm-call` is unavailable, skip silently — never block execution.

## Step 1 — Extract feature description

Read in order of preference:
1. `<feature_path>/USER_STORIES.md` — use the one-line goal from the first story
2. `<feature_path>/IMPLEMENTATION_PLAN.md` — use the first paragraph
3. Fallback: humanize the feature slug (kebab → spaces)

## Step 2 — Detect tech stack

Check in order:
- `package.json` → look for `next` → `nextjs`; `react` (without next) → `react`; `vue` → `vue`; `svelte` → `svelte`; `astro` → `astro`
- `pubspec.yaml` → `flutter`
- File extensions in `src/` → `.tsx` = `react`, `.vue` = `vue`, `.svelte` = `svelte`
- Default: `react`

## Step 3 — Run design system generation

log-phase PHASE_START design

Run: `python -c "import time; print(int(time.time()))"` and note the integer as `DESIGN_START`.

Print:
```
[DESIGNING] Generating design system for: <feature>
Stack: <stack>
Query: "<description>"
```

**Scout existing UI first (optional).** If the project already ships UI components or design
tokens, use `code-query` (appended) — or the Scout choreography (appended) where the adapter can
spawn — to find them, so the generated system extends what exists instead of conflicting with it.

**Primary — invoke `ui-ux-pro-max` skill via the Skill tool:**
Call the Skill tool with:
- skill: `"ui-ux-pro-max"`
- args: `"<description> design system for <stack> stack"`

The skill output IS the design system. Capture everything it produces.

**Fallback (if Skill tool is unavailable or returns empty output):**
```bash
pathly-design "<description>" --design-system --stack <stack> -p "<feature>"
```
If `pathly-design` is not found, fall back to `python -m pathly_data.core.design.cli`.

Capture the full output. If both methods fail, write a minimal `DESIGN.md` with the error noted and continue — do not block the pipeline.

## Step 4 — Write DESIGN.md

Write `<feature_path>/DESIGN.md`:

```markdown
# Design System — <feature>

> Generated by UI UX Pro Max · Stack: <stack> · <ISO date>

## Query
<description used>

## Design System Output

<full output from search.py>

## Builder Notes

- Reference this file when implementing UI components for this feature
- Override any recommendation that conflicts with existing project design tokens
- Stack: <stack> — use stack-specific imports and patterns from the output above
```

## Step 5 — Log and transition

log-phase PHASE_DONE design

Log to central DB:
```bash
python3 -c "from pathly_orchestrator.eventlog import append_event as _ae; ts=__import__('datetime').datetime.now(__import__('datetime').timezone.utc).strftime('%Y-%m-%dT%H:%M:%SZ'); [_ae('<feature_path>', e) for e in [{'type':'FILE_CREATED','file':'DESIGN.md','ts':ts},{'type':'STAGE_COMPLETE','stage':'DESIGNING','next':'BUILDING','ts':ts}]]"
```

Run the Completion report with `agent: designer`, `result: DONE`, `conversation: 0`, using `DESIGN_START`.

Report completion to the FSM:
```bash
pathly-fsm-call complete-stage --flow team --topic <feature> --project-root <project_root>
```

The FSM reads its transition_rules (DESIGNING → next state per the team flow definition), updates the central DB, and mirrors the new state to `<feature_path>/STATE.json`. The skill no longer writes STATE.json directly.

Print:
```
[DESIGNING] Complete. Design system written to <feature_path>/DESIGN.md
Transitioning → BUILDING
```

## Failure handling

- If `<feature_path>/` does not exist: print error, do not create DESIGN.md, do not transition.
- If search.py fails: write DESIGN.md with a note that generation failed, still log FILE_CREATED and transition — pipeline must not stall on a design step.
