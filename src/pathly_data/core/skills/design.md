# pathly-design

Design intelligence step for the Pathly pipeline.
Runs **after plan, before build** — generates a `DESIGN.md` artifact the builder uses as its visual spec.

## Step 1 — Resolve Feature & Stack

**Find active feature:**
1. List folders in `pathly/plans/` (skip `.archive/`)
2. Read `PROGRESS.md` in each — find `status: IN PROGRESS` or `Status: IN PROGRESS`
3. If none found and `$ARGUMENTS` names a feature, use that
4. If still none found, ask: `Which feature are we designing for?`

**Extract description:**
- Read `pathly/plans/<feature>/USER_STORIES.md` if present — extract the one-line goal
- Else read `pathly/plans/<feature>/IMPLEMENTATION_PLAN.md` first paragraph
- Else use the feature folder name, humanized (kebab → spaces)

**Detect tech stack:**
- Check `package.json` → look for `react`, `next`, `vue`, `svelte`, `astro`
- Check `pubspec.yaml` → Flutter
- Check file extensions in `src/` → `.tsx`=react, `.vue`=vue, `.svelte`=svelte
- Default to `react` if unclear

Map detected stack to search.py stack arg:
| Detected | Stack arg |
|---|---|
| next / nextjs | `nextjs` |
| react (no next) | `react` |
| vue | `vue` |
| nuxt | `nuxtjs` |
| svelte | `svelte` |
| astro | `astro` |
| flutter | `flutter` |
| react-native | `react-native` |
| html / other | `html-tailwind` |

## Step 2 — Run Design System Generation

Print:
```
Generating design system for: <feature>
Stack: <stack>
Query: "<description>"
```

Run:
```bash
pathly-design "<description>" --design-system --stack <stack> -p "<feature>"
```

If `pathly-design` is not found, fall back to `python -m pathly_data.core.design.cli`.

Capture the full output.

## Step 3 — Write DESIGN.md

Write `pathly/plans/<feature>/DESIGN.md` with this structure:

```markdown
# Design System — <feature>

> Generated by UI UX Pro Max · Stack: <stack> · <date>

## Query
<description used>

## Design System Output

<full output from search.py>

## Builder Notes

- Reference this file when implementing UI components for this feature
- Override any recommendation that conflicts with existing project design tokens
- Stack: <stack> — use stack-specific imports and patterns from the output above
```

## Step 4 — Print Summary

```
Design step complete.

  Feature : <feature>
  Stack   : <stack>
  Output  : pathly/plans/<feature>/DESIGN.md

Next step: /pathly build
```

If writing DESIGN.md fails (e.g., plan folder doesn't exist), print the design system output to the terminal instead and note the feature folder is missing.

## Flags via $ARGUMENTS

| Arg | Effect |
|---|---|
| `<feature-name>` | target a specific feature by name |
| `--stack <stack>` | override auto-detected stack |
| `--query "<text>"` | override auto-extracted description |

Example: `/pathly design studio-ui --stack nextjs --query "developer IDE with terminal and event log"`
