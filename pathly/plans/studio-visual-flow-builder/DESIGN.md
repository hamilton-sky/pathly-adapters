# Design System - studio-visual-flow-builder

> Generated by Pathly design step. Stack: React / Electron / React Flow. Date: 2026-05-19.

## Query

Pathly Studio visual flow builder with drag and drop agent and skill nodes, node inspector, YAML preview, validation, and export targets for Pathly package, Claude Code, and Codex.

## Design Direction

Pathly Studio should feel like an operational IDE, not a wizard-first website. The primary screen is a three-pane workflow surface:

- Left library: flows, skills, agents, templates, and workspace artifacts.
- Center canvas: graph of flow states and transitions.
- Right inspector: selected node, edge, validation, or export details.

The wizard remains useful, but only as "New Flow from Template". It should seed a graph, then hand users to the canvas. The visual graph is the main authoring model.

## Layout

```
Top bar
  project selector | target selector | file watch | terminal | publish

Left library            Center canvas                  Right inspector
  filter                  React Flow graph               node config
  flows                   zoom / fit / lock              edge config
  skills                  validation markers             YAML preview
  agents                  drop target                    export targets
  templates
  workspace

Bottom terminal / monitor panel
```

## Interaction Rules

- Dragging a skill or agent from the library onto the canvas assigns behavior to a state node or creates a new state with that behavior.
- Dragging from a node handle to another node creates a transition.
- Clicking a node opens node configuration: state id, label, assigned behavior, description, required artifacts, and entry notes.
- Clicking an edge opens transition configuration: label, conditions, artifact gates, transition actions, and feedback routing.
- The YAML tab is a live preview/edit view of the canonical flow model.
- Export is disabled until validation passes or the user explicitly accepts warnings.

## Component Behavior

### Library

- Keep sections always visible but collapsed by default for advanced areas.
- Show core flows and common behaviors first.
- Use small item rows with icon, name, type badge, and drag affordance.
- Hide internal implementation details until the user expands "Advanced".

### Canvas

- Use React Flow handles on every state node.
- Edge labels should represent route reason from the runtime schema: `default`, artifact name from `transition_rules[SOURCE].on_artifact`, content/decision route labels, feedback key, or action label.
- Nodes must stay compact and scan-friendly.
- Invalid nodes use a subtle warning badge, not oversized banners.
- Pan, zoom, fit view, and lock controls should remain stable.

### Inspector

- Prefer a docked right panel over blocking modals for normal edits.
- Use a modal only for destructive actions, export confirmation, and larger generated YAML review.
- Each inspector section should be explicit:
  - Identity
  - Assigned behavior
  - Inputs and artifacts
  - Outgoing transitions
  - Validation

### YAML Preview

- YAML preview should show generated YAML from the graph model.
- Editing YAML directly should re-parse back into the graph after validation.
- If YAML cannot parse, keep the previous valid graph visible and show the parse error.

### Export

- Export targets:
  - Pathly package
  - Claude Code
  - Codex
- One canonical flow model feeds all targets.
- Export target adapters can add host-specific wrapper files, but cannot mutate the source graph silently.

## Visual Language

- Preserve the current Pathly Studio palette and dense tool layout.
- Avoid landing-page patterns, hero sections, large decorative gradients, and card-heavy marketing composition.
- Use compact controls, visible focus states, and clear hover feedback.
- Use Lucide icons for add, connect, validate, export, lock, fit view, and warnings.
- Keep border radius at 4-6px for tool surfaces.

## Design Tokens And Accessibility

Use only existing theme tokens from `useTheme` (`t.bgBase`, `t.bgSurface0`, `t.bgSurface1`, `t.bgMantle`, `t.accent`, `t.blue`, `t.green`, `t.textPrimary`, `t.textSecondary`, `t.textMuted`, `t.border`, `t.borderSubtle`). Do not introduce new hex literals.

- Border radius: 4-6px for tool surfaces, 6px for cards and inspectors.
- Spacing rhythm: 4 / 8 / 12 / 16 px. Inspector internal gap: 8px.
- Font sizing: existing Studio scale via CSS vars (`var(--font-size-sm)`, `var(--font-size-base)`). Use monospace only for state ids, agent slugs, and YAML preview.
- Contrast: every text/background pair must meet 4.5:1 in the active theme. Validate against both light and dark themes.
- Focus: every interactive surface (drag handle, node, edge, inspector input, target dropdown) must have a visible focus ring using `t.accent`. Never remove default focus rings without replacement.
- Motion: transitions 150-250ms; respect `prefers-reduced-motion` and disable non-essential motion when set.

### Z-Index Scale

Use one explicit scale across the visual editor so popovers, inspector, validation toasts, and export confirmation never clip each other.

| Layer | z-index | Used by |
|---|---|---|
| Canvas content | 0 | React Flow nodes, edges, controls |
| Docked inspector | 10 | Right inspector panel |
| Popover | 40 | Behavior picker, target dropdown |
| Toast / banner | 60 | Save and export feedback |
| Modal | 100 | Destructive confirm, export confirmation |

## Validation UX

Validation should run continuously and before save/export.

Required checks:

- Every state exists in `states`.
- Every transition source and target exists.
- Every `transition_rules` source exists and uses the state-keyed runtime schema.
- Every `transition_rules` target (`default`, `on_artifact`, `on_content.next`, `decide.options`) is listed in `transitions[source]`.
- Every `transition_actions` key uses `SOURCE->TARGET` or `->TARGET` and points to known states/transitions.
- Every non-terminal state has at least one outgoing transition.
- Every referenced agent or skill exists or is marked external.
- `DONE` or terminal states have no required outgoing transition.
- YAML parse errors do not destroy the last valid graph.
- Export target compatibility warnings are visible before export.

Issue display rules:

- Node-level issues attach a subtle warning badge to the affected state node, not a banner.
- Edge-level issues color the affected edge using `t.destructive` or `t.warning` (whichever exists in the theme) and surface the message in the edge inspector.
- Inspector field issues appear inline below the field with `role="alert"` and `aria-live="polite"`. Do not use placeholder-only labels.
- Inputs validate on blur, not on every keystroke. Submit-time checks remain.
- Export is disabled while errors exist. Warnings require explicit acknowledgement.

## Behavior Picker (Node Inspector)

The assigned-behavior picker is a popover, not a modal. It opens from the inspector's "Assigned behavior" row.

- Trigger: a single inline control showing the current behavior (or `(none)`), styled as a chip-style button.
- Popover content: searchable list with type filter (skill, agent, external). Items show name, type badge, and source path. Up/down arrows and Enter select. Esc closes.
- Empty result: helpful message ("No matches. Drop a file into Skills or Agents.") with no destructive action.
- Selecting an item writes `agent_map[stateId]` and closes the popover. Missing-on-disk items remain selectable but show a warning badge in the inspector.

## Export Controls

Export controls live in the top-right of the canvas toolbar.

- A target dropdown lists Pathly package, Claude Code, and Codex.
- An adjacent `Export` button is disabled when validation has errors.
- Warnings show an inline chip near the button. Clicking the button when warnings exist opens a confirmation modal that lists each warning and requires explicit acknowledgement.
- Successful export shows a transient toast (auto-dismiss 3-5s) with a copy-path action.

## Empty States

- Empty canvas (a freshly created flow with no states): show a low-emphasis hint in the canvas center ("Drag a skill or agent from the library, or click + to add a state."). No oversized illustration.
- Empty library section: show the same compact "+ new" affordance the sidebar already uses. Do not redesign the existing sidebar empty state in this feature.
- Inspector with nothing selected: show a one-line hint ("Select a node or edge to edit."). No card chrome.

## Layout Constraint

The inspector is a docked third pane inside `VisualView`, not an overlay over the canvas. Implementation must update `VisualView.styles.ts` so:

- Canvas and inspector are siblings in a flex row.
- Inspector width is 280-320px, resizable later but fixed for this feature.
- Closing the inspector returns the canvas to full width without remounting React Flow.
