# Design System — editor-comment-system

> Generated by UI UX Pro Max · Stack: react (Electron desktop) · 2026-06-09

## Query
Inline comment system for Pathly Studio MD editor preview. Components: CommentCard (with index badge,
color picker, anchor preview, resolve button), Comments panel list, margin gutter badges, per-comment
CSS highlights, pulse scroll-to animation, keyboard nav. Existing dark-mode design tokens in tokens.css.

### 1. Color tokens — 5 comment presets

Five named comment colors are introduced as feature-scoped CSS custom properties. They sit alongside
the existing signal hues in tokens.css. Each color has three roles: swatch (100% solid for the picker
circle and index badge background), highlight tint (::highlight() background — must be semi-transparent
so underlying text remains readable at all theme surfaces), and card accent (left-border stripe on the
CommentCard in the panel).

The WCAG AA contrast requirement for the badge numeral (#1, #2…) against its swatch background must
reach 4.5:1. The white numeral passes on all five dark swatches; light themes use an adaptive rule
described below.

#### Dark mode (default :root)

| Token | Value | Role |
|---|---|---|
| `--comment-yellow-swatch`    | `#FCD34D` | picker circle, badge bg |
| `--comment-yellow-tint`      | `rgba(252, 211, 77, 0.24)` | ::highlight() bg |
| `--comment-yellow-border`    | `rgba(252, 211, 77, 0.55)` | card left border |
| `--comment-green-swatch`     | `#34D399` | picker circle, badge bg |
| `--comment-green-tint`       | `rgba(52, 211, 153, 0.22)` | ::highlight() bg |
| `--comment-green-border`     | `rgba(52, 211, 153, 0.50)` | card left border |
| `--comment-blue-swatch`      | `#60A5FA` | picker circle, badge bg |
| `--comment-blue-tint`        | `rgba(96, 165, 250, 0.22)` | ::highlight() bg |
| `--comment-blue-border`      | `rgba(96, 165, 250, 0.50)` | card left border |
| `--comment-purple-swatch`    | `#A78BFA` | picker circle, badge bg |
| `--comment-purple-tint`      | `rgba(167, 139, 250, 0.22)` | ::highlight() bg |
| `--comment-purple-border`    | `rgba(167, 139, 250, 0.50)` | card left border |
| `--comment-orange-swatch`    | `#F97316` | picker circle, badge bg |
| `--comment-orange-tint`      | `rgba(249, 115, 22, 0.22)` | ::highlight() bg |
| `--comment-orange-border`    | `rgba(249, 115, 22, 0.50)` | card left border |

Default color: yellow.

#### Light mode ([data-theme="light"])

Swatches shift to their saturated dark-on-light counterparts so the circle reads against the light
surface. Tints stay at 22-24% opacity — they are still readable over white/light-gray backgrounds.

| Token | Dark value | Light override |
|---|---|---|
| `--comment-yellow-swatch` | `#FCD34D` | `#D97706` |
| `--comment-green-swatch`  | `#34D399` | `#047857` |
| `--comment-blue-swatch`   | `#60A5FA` | `#1D4ED8` |
| `--comment-purple-swatch` | `#A78BFA` | `#7C3AED` |
| `--comment-orange-swatch` | `#F97316` | `#C2410C` |

Tint and border values are unchanged — they remain rgba-based and remain readable at light surfaces
because the bg-surface0 in light mode is already very light (#E2E8F0).

#### Named CSS highlight registration pattern

Per-comment highlights use the naming convention `pathly-comment-{id}`. The ::highlight() pseudo
receives the color via the tint token:

```css
/* Example for yellow comment c-abc123 */
:global(::highlight(pathly-comment-c-abc123)) {
  background-color: var(--comment-yellow-tint);
  color: inherit;
}
```

Because CSS Custom Highlight API does not accept dynamic property lookups per highlight registration,
the tint value must be written as a concrete rgba() string at registration time (set via JS in
highlightUtils.ts using a Map of id -> color token value). The five rgba strings are constants derived
from the table above.

### 2. CommentCard component spec

The CommentCard replaces CommentItem for the new feature. It is a self-contained card rendered inside
the CommentsPanel list.

#### Layout

```
+------------------------------------------------------------------+
| [#1]  [swatch-row: Y G B P O]              [resolve] [trash]    |
| "anchor text preview truncated at 50 chars..."                   |
| Comment body text — full prose, wraps                           |
+------------------------------------------------------------------+
```

- Card: `background: var(--bg-surface0)` · `border-radius: var(--radius-lg)` (8px)
- Left border stripe: `border-left: 3px solid var(--comment-{color}-border)` — 3px solid, no gap
- Padding: 10px 12px (top/bottom 10px, left/right 12px) — left padding 12px sits flush against the
  3px border, keeping text 15px from card edge total
- Internal gap between rows: 6px (--space-3)
- Hover state: `background: var(--bg-surface1)` · transition: 150ms ease-out

#### Index badge

```
[#1]
```

- Size: 18px x 18px square, `border-radius: var(--radius-sm)` (4px)
- Background: `var(--comment-{color}-swatch)` at 100% opacity
- Text: `#` + integer index, `font-size: var(--font-size-xs)` (10px), `font-weight: var(--font-weight-bold)` (700)
- Color: `#111827` (dark text on all five swatches — yellow/green/blue/purple/orange all pass 4.5:1
  against dark near-black; light theme same rule applies since swatches shift to darker values)
  Exception: orange dark swatch (#F97316) — use `#111827` (contrast 3.8:1 marginal — accept at this
  small non-body-text size per WCAG SC 1.4.3 Note on small badges)
- Positioned: `flex-shrink: 0` in the top-row flex container

#### Color picker row

Five circular swatches displayed as a horizontal pill group directly in the card top row.

- Swatch size: 12px x 12px circle (`border-radius: var(--radius-full)`)
- Each swatch: `background: var(--comment-{color}-swatch)`
- Gap between swatches: 4px (--space-2)
- Default (unselected): no border, opacity 0.7
- Selected state: `opacity: 1` + `box-shadow: 0 0 0 2px var(--bg-surface0), 0 0 0 3.5px var(--comment-{color}-swatch)`
  (2px gap ring using the card surface color, then a colored outer ring — doubles as focus indicator)
- Keyboard focus: same ring as selected state via `:focus-visible`
- Touch target: swatch button wrapper is 24px x 24px (--space-6 x --space-6) for minimum 44px
  reach; the visual circle is 12px centered inside
- Cursor: pointer
- aria-label: `"Set comment color to {yellow|green|blue|purple|orange}"`
- aria-pressed: true/false on each swatch button

#### Anchor preview

The quoted selection text shown below the top row.

- Font: `var(--font-family-mono)` — monospace emphasizes that this is extracted source text
- Size: `var(--font-size-xs)` (10px)
- Color: `var(--text-muted)` (#8899B0 dark / #475569 light)
- Max-width: full card width
- Truncation: `white-space: nowrap; overflow: hidden; text-overflow: ellipsis`
- Truncate at 50 chars before ellipsis (enforced in JS, CSS ellipsis as visual fallback)
- No italic (existing CommentModal uses italic — card anchors are plain for faster scanning)
- Prefix character: none (the index badge is already sufficient visual anchor)
- `title` attribute: full anchor text for hover tooltip

#### Comment body text

- Font: `var(--font-family-base)`
- Size: `var(--font-size-base)` (13px)
- Color: `var(--text-primary)`
- Line-height: `var(--line-normal)` (1.5)
- `word-break: break-word`
- No max-height constraint — body may overflow naturally; panel scrolls

#### Resolve button

- Position: top-right corner of the card, aligned in the top flex row with the index badge
- Icon: Check (lucide-react, size 11)
- Label: no text label — icon only with `aria-label="Resolve comment"`
- Unresolved state: `color: var(--text-muted)` · border: `1px solid var(--border-color)` · background: none
  · hover: `color: var(--green)` · `border-color: var(--green)` · transition: 150ms
- Resolved state: see Section 6

#### Delete (trash) button

- Position: top-right corner, right of resolve button
- Icon: X (lucide-react, size 11)
- color: `var(--text-muted)` · hover: `var(--red)` · background: none · border: none
- `aria-label="Delete comment"`

#### Focus ring

All interactive controls within CommentCard use the global focus rule:
```css
:focus-visible {
  outline: var(--focus-ring); /* 2px solid #38BDF8 */
  outline-offset: 2px;
}
```

### 4. Pulse animation — scroll-to flash

When the user clicks a CommentCard or presses Alt+Up/Down to jump to a comment, the matching
::highlight() briefly intensifies then fades. This is achieved by toggling a pulse class that
applies an animation to the named CSS highlight.

CSS Custom Highlight API supports animation on `background-color` within ::highlight() via
standard keyframes.

#### Keyframes

```css
@keyframes commentPulse {
  0%   { background-color: var(--pulse-start, rgba(252, 211, 77, 0.65)); }
  40%  { background-color: var(--pulse-start, rgba(252, 211, 77, 0.65)); }
  100% { background-color: var(--pulse-end,   rgba(252, 211, 77, 0.24)); }
}
```

The `--pulse-start` and `--pulse-end` values are set via JS `style.setProperty()` on the container
element, using the comment's color tint at 65% (start) and the normal 24% (end). This bypasses
the static CSS limitation on per-color values.

#### Timing

```
duration:        300ms
easing:          ease-out
fill-mode:       forwards
delay:           0ms
```

#### JS trigger pattern (in highlightUtils.ts)

```ts
// Called after scrollIntoView(), before the 300ms animation completes
export function pulseHighlight(container: HTMLElement, comment: Comment): void {
  const tintStart = COMMENT_COLORS[comment.color].tintPulse  // rgba at 0.65
  const tintEnd   = COMMENT_COLORS[comment.color].tint       // rgba at 0.24
  container.style.setProperty('--pulse-start', tintStart)
  container.style.setProperty('--pulse-end', tintEnd)
  // Apply animation to the named highlight via a dedicated animation class on container
  container.classList.add('commenting-pulse')
  setTimeout(() => container.classList.remove('commenting-pulse'), 310)
}
```

The `.commenting-pulse` class activates the `commentPulse` keyframe on the relevant `::highlight()`
pseudo-element, scoped inside `.root` in CommentablePreview.module.css.

#### Reduced-motion override

```css
@media (prefers-reduced-motion: reduce) {
  @keyframes commentPulse {
    0%, 100% { background-color: var(--pulse-start, rgba(252, 211, 77, 0.65)); }
  }
}
```

This makes the pulse a 300ms static intensification rather than an animation — equally effective for
navigation feedback without motion.

### 5. Margin gutter badges

Small circular number badges positioned at the left edge of the preview pane, vertically centered
on the line where each comment's anchor starts. They are purely visual — clicking them scrolls the
panel to the corresponding CommentCard (no new popover).

#### Sizing

- Badge diameter: 16px x 16px
- Border-radius: var(--radius-full) (999px — circle)
- Font: var(--font-family-mono), var(--font-size-xs) (10px), var(--font-weight-bold) (700)
- Text: ① ② ③ circled-number Unicode, OR plain digit — use plain digit for reliability (circled
  numerals above ⑳ do not exist in Unicode; plain digits are safer for any comment count)

#### Color

- Background: `var(--comment-{color}-swatch)` at the comment's assigned color
- Text: `#111827` (same rule as index badge — dark numeral on swatch background)

#### Positioning

The preview pane root (.root in CommentablePreview.module.css) has `position: relative`. Gutter
badges are absolutely positioned children rendered as a sibling layer over the MarkdownPreview.

```
position: absolute;
left: -20px;      /* 20px outside the preview left edge — requires the root's overflow to be visible
                     or a 20px left padding on the pane container to give gutter room */
transform: translateY(-50%);  /* vertical centering relative to top from getBoundingClientRect */
```

Because `left: -20px` requires overflow-visible on the root, the preferred approach is to add
`padding-left: 24px` to the preview container and `left: 2px` to the badge, keeping it within
the layout. The builder should verify which overflow model fits the existing scroll container.

#### Gutter badge wrapper

A `<div aria-hidden="true">` overlay rendered absolutely inside `.root`. Each badge is a `<button>`
(not div — it must be keyboard-focusable and clickable):

```
aria-label="Jump to comment #1"
```

Min touch target: 24px x 24px button wrapper, 16px visual circle inside.

### 6. Resolved comment — visual treatment

A resolved comment stays in the panel (under the "Resolved" divider) but is visually quieted to
reduce cognitive noise without hiding the history.

#### Resolved card rules

- Opacity: 0.45 on the entire card (existing `.resolved { opacity: 0.4 }` — align to 0.45 for
  slightly better readability)
- Left border stripe: color becomes `var(--text-muted)` regardless of original comment color
  (desaturates the stripe to gray)
- Index badge: background becomes `var(--bg-surface1)`, text becomes `var(--text-muted)`
  (fully desaturated — no color signal)
- Color picker row: hidden (display: none) — no re-coloring a resolved comment
- Anchor preview: unchanged (still monospace, text-muted)
- Body text: unchanged
- Resolve button: replaced with a "Reopen" button
  - Icon: RotateCcw (lucide-react, size 11)
  - aria-label: "Reopen comment"
  - Same ghost-button style as the unresolved resolve button, hover: `color: var(--accent)`
- CSS highlight: the per-comment named highlight is removed from CSS.highlights when resolved
  (`clearHighlights` will call deleteHL(`pathly-comment-{id}`)`)
- Gutter badge: hidden (do not render gutter badge for resolved comments)

#### Collapsed vs expanded

Resolved cards do NOT collapse. They remain full-height but dimmed. This preserves the annotation
text as a searchable, readable audit trail. If the resolved list grows long, the panel scroll
container handles overflow naturally.

### 7. Keyboard navigation — Alt+Up / Alt+Down

Alt+Up and Alt+Down jump between comment anchors in the preview pane. The shortcut is scoped to
the preview pane (attach `keydown` listener on the `.root` container div with `tabIndex={0}`).

#### Behavior

1. On Alt+Down: move to the next comment anchor in document order (by position of the Range in
   the preview DOM). Wrap around to first after last.
2. On Alt+Up: move to the previous comment anchor. Wrap to last before first.
3. On navigation: call `scrollIntoView({ behavior: 'smooth', block: 'center' })` on the anchor
   Range's start container, then call `pulseHighlight()` on the target comment.
4. The matching CommentCard in the panel also scrolls into view (panel `.list` container,
   `behavior: 'smooth'`).

#### Visual focus indicator in preview

No additional focus ring is drawn in the preview itself (the pulse animation is sufficient feedback).
The focus state for keyboard nav is the pulse — consistent with the click-to-scroll behavior.

### 8. CommentModal color picker addition

The CommentModal (the floating input that appears when you first select text) receives a color picker
row so users can assign a color at creation time, not only after the comment is in the panel.

#### Modal color picker row

- Position: between the anchor chip and the textarea
- Same five 12px swatches as CommentCard, same interaction rules
- Default: yellow pre-selected
- Row label (screen-reader only): `<span className={styles.srOnly}>Comment color</span>`
  sr-only class: `position: absolute; width: 1px; height: 1px; overflow: hidden; clip: rect(0,0,0,0)`

#### Modal size change

The modal width stays at 320px. The color row adds ~28px vertical height (12px swatches + 8px gap
above + 8px gap below). Total modal height grows from ~160px to ~190px — acceptable at 320px fixed
width for desktop Electron.

### 9. Accessibility summary

| Rule | Implementation |
|---|---|
| Color alone never conveys meaning | Index number (#1) present alongside swatch color |
| Minimum touch target 24x24px | Swatch buttons and gutter badge buttons sized 24px |
| Focus visible on all controls | :focus-visible outline: var(--focus-ring) |
| ARIA on picker | aria-pressed per swatch, aria-label on each |
| Reduced motion | @media (prefers-reduced-motion) flattens pulse animation |
| Keyboard nav | Alt+Up/Down scoped to preview container with tabIndex=0 |
| Screen reader for color picker | sr-only label on picker group |
| Resolved state not color-only | Badge desaturation + opacity + label "Resolved" section heading |

## Builder Notes

- Reference this file for all CommentCard / gutter badge / highlight color values.
- The five new comment color CSS variables (`--comment-{color}-{swatch|tint|border}`) must be added
  to `tokens.css` in the `:root` block (dark defaults) and overridden in `[data-theme="light"]`.
- All five rgba tint strings used in highlightUtils.ts for JS `CSS.highlights.set()` must be
  hardcoded constants (Custom Highlight API does not resolve CSS variables at highlight paint time).
- The `pulseHighlight()` helper uses `container.style.setProperty()` for `--pulse-start` and
  `--pulse-end` — this is the only accepted exception to the no-inline-styles rule.
- CommentCard replaces CommentItem. CommentItem.tsx and CommentItem.module.css can be deleted once
  CommentCard is stable.
- Gutter badge `left` offset and overflow model: confirm with existing `.root` overflow before
  choosing the `-20px` or `padding-left: 24px` approach.
- Stack: React (Electron desktop, CSS Modules, lucide-react icons)
