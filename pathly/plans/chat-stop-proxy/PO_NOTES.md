# PO Notes — chat-stop-proxy
_Generated by PO advisor (auto-flow mode)_

## Problem & Users
Pathly Studio chat users currently cannot cancel a long or wrong-direction LLM
stream — they must wait it out, wasting time and tokens. Separately, power users
who already drive Claude Code via the embedded PTY terminal want to use the
chat panel as a clean conversational front-end to Claude Code without
context-switching to the terminal pane. Primary user: the Pathly Studio
developer using the chat panel daily.

## MVP Scope

### Feature 1 — Stop/Abort Button
- While `isLoading === true`, the Send button transforms into a Stop button.
- Stop button is enabled (clickable) during streaming.
- Stop button has a distinct visual identity (square/stop icon, different
  color treatment) consistent with the existing dark-theme + accent styling.
- Clicking Stop aborts the in-flight LLM stream mid-response via an
  `AbortController` wired into both `askOllama` and `askLlm` paths.
- On abort: the last message's status flips from `streaming` to `done`.
- On abort: the partial response text already received remains visible in the
  chat bubble.
- After abort: the button returns to its normal Send state and the input is
  usable again.

### Feature 2 — Chat-as-Claude-Code Proxy
- Add a mode toggle to `ChatInput` with two states: `Chat LLM` and `Claude Code`.
- In `Claude Code` mode, pressing Send routes the message to the Claude Code
  PTY terminal via `writeToTerminal` instead of `askOllama` / `askLlm`.
- Terminal output streams back into the chat panel as a normal assistant
  bubble (status: `streaming` → `done`).
- The Claude Code terminal does not need to be visible/open for the proxy to
  work — only launched/attached.
- "Response complete" detection reuses the existing 12-second idle timer +
  prompt detection already implemented in `launchTerminal.ts`.
- Toggle is visually clear, low-clutter, and consistent with existing
  ChatInput styling (ui-ux-pro-max design pass).
- Mode selection persists for the session (in-memory is acceptable for MVP).

## Out of Scope
- Persisting the mode toggle across app restarts (session-only is fine).
- Streaming partial terminal output token-by-token with custom parsing —
  rely on existing terminal stream + idle/prompt detection.
- Aborting an in-flight Claude Code request (Feature 1 abort applies to LLM
  paths only for MVP; Claude Code cancellation is a future enhancement).
- Multi-turn conversational context management on the Claude Code side beyond
  what Claude Code itself maintains.
- New keyboard shortcuts for Stop or mode switching.
- Telemetry / analytics for stop usage or mode usage.
- Showing a visible "aborted" badge on the partial message (status `done` is
  sufficient for MVP).
- Changes to non-chat surfaces (sidebar, settings, command palette).

## Success Criteria
- User can click Stop during any LLM stream and the stream halts within ~1s.
- After Stop, the partial text is preserved and the message status is `done`.
- No orphaned `streaming` states remain in `chatStore` after a Stop action.
- Switching to `Claude Code` mode and sending a message produces an assistant
  bubble whose content is the Claude Code response, terminated by the existing
  idle/prompt detection.
- Switching back to `Chat LLM` mode restores normal Ollama/LLM behavior.
- No regressions in the existing Send → stream → done happy path.
- UI passes ui-ux-pro-max review: Stop button reads as distinct from Send;
  mode toggle does not visually clutter ChatInput.

## Constraints
- Electron renderer environment — no WebGPU/WebLLM.
- Must integrate with existing `chatStore` (`isLoading`, `outputByTarget`) and
  the streaming flow in `ChatPanel/index.tsx` lines 226-404.
- Send button lives at `ChatInput.tsx` lines 94-105 — transformation happens
  in-place, no layout shift.
- `AbortController` does not currently exist in the call paths — must be
  introduced and threaded through both `askOllama` and `askLlm`.
- `writeToTerminal` (`lib/launchTerminal.ts`) is the only sanctioned way to
  push input to the Claude Code PTY.
- Reuse the existing 12-second idle timer + prompt detection in
  `launchTerminal.ts` — do not invent a parallel detection mechanism.
- Dark theme + existing accent color palette must be preserved.

## Edge Cases & Risks
- Stop clicked after stream already completed (race) — must be a safe no-op.
- Stop clicked before any tokens received — message should still resolve to
  `done` with empty/partial content rather than getting stuck.
- Network error mid-stream — existing error handling must still mark `done`
  and not be masked by abort logic.
- Mode toggled mid-stream — define behavior: in-flight request finishes under
  its original mode; new sends use the new mode.
- Claude Code mode used when terminal has not been launched yet — must
  auto-launch or surface a clear, recoverable message.
- Claude Code idle-timer false positives (long-running command produces no
  output for 12s) — accepted MVP limitation; document it.
- Multiple rapid Sends in Claude Code mode — queue or block until previous
  response detected as done (recommend: block Send while `isLoading`).
- Partial UTF-8 / ANSI escape sequences from PTY landing in chat bubble —
  ensure existing terminal-output sanitization is applied before display.
