# PO Notes — fsm-friction-fixes
_Generated by PO advisor (autoFlow / po-confirm pass over rich STORM_SEED.md)_

## Problem & Users

Three independent friction points in the Pathly FSM degrade the experience of
every contributor running a feature through the pipeline: (1) FSM HTTP server
fails to auto-start cleanly, forcing a manual terminal context switch; (2) the
scope gate flags pre-existing dirty files as "out of scope" because it diffs
against a SHA instead of tracking what the builder actually touched; (3)
multi-conversation routing depends on the reviewer remembering to emit
`MORE_CONVS_NEEDED.md`, which silently advances the FSM past unfinished work
when forgotten. Primary users are Pathly contributors running `/pathly` skills;
secondary users are reviewers and the FSM itself (self-modifying features).

## MVP Scope

### User Story 1 — FSM server auto-start (zero-touch)

**As a** Pathly contributor invoking any `/pathly` skill
**I want** the FSM HTTP server to start reliably on first call without me
opening a terminal
**So that** I never see "FSM server unavailable" mid-skill.

Acceptance criteria:
- `ensure_server_running` in `src/pathly_orchestrator/fsm_http_client.py`
  replaces the fixed 2 s sleep with a poll loop (≤30 attempts × 250 ms = 7.5 s
  ceiling, exits early on first 200 from `/health`).
- `_start_server` writes a PID file to `<user_cache>/pathly/fsm.pid` before
  spawning; if PID exists and is alive, skips spawn and proceeds straight to
  polling.
- On POSIX: child spawned with `start_new_session=True` (immune to parent
  SIGHUP). On Windows: child spawned with
  `CREATE_NEW_PROCESS_GROUP | DETACHED_PROCESS`.
- `src/pathly_data/core/skills/utilities/fsm-call.md` steps 2 and 3 collapse
  into a single instruction to call `pathly-fsm-call …`. The broken
  `python -m pathly_orchestrator.http_server &` fallback is removed entirely.
- `src/pathly_orchestrator/http_server.py` adds a `/health` route that returns
  200 before logging / rate-limit middleware so probes are fast and unmetered.
- Cold-start adds at most ~7.5 s to the first skill call in a session;
  subsequent calls hit the warm server within the existing health-check budget.

### User Story 2 — Scope gate tracks touched files (not SHA delta)

**As a** Pathly contributor with uncommitted unrelated edits in my working
tree
**I want** the scope gate to only flag files the builder actually wrote during
the conversation
**So that** my pre-existing local changes don't cause SCOPE_VIOLATION
false positives.

Acceptance criteria:
- On `next_action` entering a BUILDING state, `fsm_ops.py` snapshots the
  current set of modified/untracked files (via `git status --porcelain=v1 -z`)
  and persists them to `STATE.json["build_baseline"]["preexisting_dirty"]`,
  with an ISO `started_at` timestamp.
- `_scope_clean` in `fsm.py` is rewritten with signature
  `_scope_clean(storage_path, scope_file, preexisting_dirty: set[str] | None) -> bool`:
  it reads `build_baseline.preexisting_dirty`, subtracts it from
  `git diff --name-only HEAD` plus untracked files, and compares the
  remainder against the declared scope.
- The exemption for `src/pathly_orchestrator/` is removed from `_is_exempt`
  (that exemption masked the bug). Exemptions for `pathly/plans/` and
  `*.tsbuildinfo` remain — those are genuine non-user artifacts.
- `complete_stage` clears `build_baseline` alongside `conv_start_sha` so the
  next conversation re-baselines fresh.
- If `build_baseline.preexisting_dirty` exceeds 500 entries, the gate emits a
  `GATE_DEGRADED` event and falls back to permissive mode.
- Missing `build_baseline` on legacy STATE.json files emits `GATE_SKIPPED`
  with reason `no_build_baseline`; no auto-migration writes occur.

### User Story 3 — Multi-conversation routing as a first-class FSM concept

**As a** Pathly contributor running a multi-conversation feature plan
**I want** the FSM to know how many conversations the plan declared and route
explicitly on a counter
**So that** reviewer forgetfulness can never advance the FSM past unfinished
work.

Acceptance criteria:
- `fsm_ops.py` exposes `_count_planned_convs(storage_path: Path) -> int`,
  counting `| N |` rows in `PROGRESS.md`. Returns 0 if absent (legacy
  single-conv flow).
- On first `next_action` for a feature, FSM persists
  `STATE.json["convs_total"]` and `STATE.json["convs_done"] = 0`.
- A new transition rule level **`on_state_counter`** is added to
  `evaluate_transition_rules` with the generic schema (option A, confirmed
  by user):
  ```yaml
  on_state_counter:
    field: convs_done
    op: lt          # one of: lt, lte, eq, gte, gt, ne
    compare_to: convs_total   # another STATE.json field
    next: BUILDING
  ```
  Evaluator compares two STATE.json integer fields; returns next-state string
  on match, falls through on miss.
- `team.flow.yaml` REVIEWING block uses `on_state_counter` to route
  `convs_done < convs_total → BUILDING`; existing
  `on_artifact: MORE_CONVS_NEEDED.md: BUILDING` stays as backwards-compat
  fallback for one release.
- The `update_progress` transition action increments
  `STATE.json["convs_done"]` atomically when `mark: conv_done`.
- `core/skills/team/review.md` removes the "write
  `MORE_CONVS_NEEDED.md`" instruction (line 177); reviewer no longer drives
  routing manually.
- On every `next_action`, FSM re-reads PROGRESS.md row count and emits a
  warning event if it differs from persisted `convs_total`. Does not
  auto-correct.

## Out of Scope

- **No new `pathly-fsm-call` CLI flags.** The existing CLI contract stays
  intact; the auto-start fix is internal to `ensure_server_running`.
- **No OS-level service registration** (no Windows scheduled task / launchd
  plist / systemd user unit). The architect rejected this alternative.
  Lazy-start-on-first-call remains the contract.
- **No `BUILDER_TOUCHED.md` manifest** written by the builder. Gate
  enforcement reads filesystem state, not builder self-reports.
- **No reviewer `decide` block** asking "more conversations needed?". Plan
  declares the count; FSM enforces it.
- **No removal of `on_artifact: MORE_CONVS_NEEDED.md`** in this release.
  Kept as backwards-compat fallback for one release cycle.
- **No auto-migration of legacy STATE.json files.** Old plans without
  `build_baseline` or `convs_total` keys emit `GATE_SKIPPED` events with
  appropriate reasons; they re-baseline organically on next `next_action`.
- **No Studio / Electron UI changes** in this feature.

## Success Criteria

- Zero "FSM server unavailable" errors observed on a clean cold-start across
  Windows, macOS, Linux when invoking any `/pathly` skill.
- A working tree with arbitrary pre-existing dirty files passes the scope
  gate as long as the builder only touches declared paths. Verified by
  running this very feature through its own pipeline (the gitStatus at
  STORM_SEED time shows `SKILL_EXECUTION.md` and `test_setup.py` already
  dirty).
- Multi-conversation plans (≥2 conversations declared in PROGRESS.md) cannot
  advance from REVIEWING to TESTING until `convs_done == convs_total`, even
  if the reviewer writes nothing.
- All existing tests in `tests/test_gates.py` and `tests/test_fsm_ops.py`
  either pass unchanged or are rewritten to match the new contract; no test
  is silently deleted.
- New tests cover `on_state_counter` evaluator paths: condition met, condition
  unmet, missing counter field, malformed rule.

## Constraints

- **Must not break existing tests** without rewriting them to the new
  contract. Specifically: `test_scope_gate_pass`,
  `test_scope_gate_fail_undeclared_path`, and `test_scope_gate_no_baseline_sha`
  in `tests/test_gates.py` will need rewrites — that is acceptable and
  expected, but they must be replaced, not deleted.
- **Must stay backward-compatible for one release** on the
  `MORE_CONVS_NEEDED.md` artifact path. Reviewer outputs from older skill
  versions must still route correctly.
- **STATE.json schema additions must be additive.** Existing readers
  (`eventlog.py:read_state`, Studio STATE.json renderer) must use `.get()`-style
  access. Confirm no enumerator iterates all keys assuming a fixed shape.
- **Adapter sync is mandatory.** Any change to `core/skills/team/review.md`
  or `core/skills/utilities/fsm-call.md` requires running
  `pathly-setup claude --apply` and `python -m build` to propagate to codex
  and copilot adapters.
- **CONVERSATION_PROMPTS.md for conv 2 and conv 3 must explicitly declare
  `src/pathly_orchestrator/fsm.py` and `src/pathly_orchestrator/fsm_ops.py`**
  since removing the self-modification exemption (conv 2) means these
  fixes can no longer touch the FSM without declaring it.
- **No commit policy violation:** never push to master without explicit user
  request (per project CLAUDE.md).

## Edge Cases & Risks

- **Stale Windows PID files.** A crashed prior session leaves a PID that
  may now belong to an unrelated process. Mitigation: always probe `/health`
  before trusting the PID; PID is a hint, health is the truth.
- **Concurrent skill invocations race on port 8645.** PID file + health
  probe prevents spawn-storm; loser detects "already starting" via PID file
  and polls.
- **Snapshot races on scope baseline.** User edits a file between
  `next_action`'s baseline snapshot and builder's first edit → file gets
  exempted as "preexisting dirty" and any builder change isn't flagged.
  Accepted: gate is belt-and-braces against builder runaway, not a primary
  authorization control. CONVERSATION_PROMPTS.md is the primary scope
  declaration.
- **Large `preexisting_dirty` sets.** Bounded at 500 entries with
  `GATE_DEGRADED` event and permissive fallback.
- **PROGRESS.md edited mid-feature.** FSM warns on row-count mismatch but
  does not auto-correct. User must explicitly reset via CLI flag if intended.
- **Conv 3 ships before Conv 2.** Interim period has counter-driven
  REVIEWING→BUILDING loop with the still-broken SHA-based scope gate.
  Acceptable: no worse than today's behavior.
- **Conv 2 ships before Conv 3.** No interaction; conv 2 is self-contained.
- **Schema-additive STATE.json key collisions.** `build_baseline` and
  `convs_total` are disjoint keys; no merge conflict between conv 2 and
  conv 3 work.

## Key Decisions Captured

- **`on_state_counter` schema: generic (option A).** User confirmed the
  evaluator takes a generic
  `{field, op, compare_to, next}` rule that compares two STATE.json fields
  with one of `lt|lte|eq|gte|gt|ne`. This is reusable for future counter-driven
  routing beyond the conv-progress case (e.g., retry budgets, gate-attempt
  caps). Rejected: a hard-coded "convs" comparator that would only work for
  this one case.
- **Conversation ordering.** Three conversations, one per problem, in order
  1 → 2 → 3. Problem 1 first because it makes iteration on Problems 2 and 3
  less painful (no "FSM server unavailable" mid-test).
- **One-release backwards-compat window** for `MORE_CONVS_NEEDED.md`
  artifact routing.
