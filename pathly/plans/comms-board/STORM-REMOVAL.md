# STORMING Removal — Audit & Plan

**Date:** 2026-06-10  
**Reason:** The new consultation flow replaces the storm phase. STORMING is a one-shot
state that is always skipped (verified: `team.flow.yaml` → `transitions: STORMING: [PLANNING]`,
no rules, no self-loop). Cut it.

---

## 1. Two separable things

| Thing | What it is | Action |
|---|---|---|
| `STORMING` | the FSM **state** in the pipeline flows | **Remove** — this is the goal |
| `storm` / `STORM_SEED.md` | the brainstorm **skill** + seed file | **Supersede** by consult flow; deprecate later (harmless if left standing) |

Removing the state does NOT require deleting the storm skill on day one. The minimal,
safe change is Tier 1 + Tier 2 below. Skill/agent rewiring (Tiers 3–6) follows as the
consult flow lands.

## 3. Removal order (safe, incremental)

```
Step 1  Tier 1 — remove STORMING from team.flow.yaml + test.flow.yaml + fsm_ops.py + skills.py
        → pipeline now enters at PLANNING. Backend done.
Step 2  Tier 2 — update Studio state lists
        → UI no longer shows a dead STORMING state.
Step 3  Add a STORMING→PLANNING recovery shim in FSM recovery
        → any in-flight STATE.json with current=STORMING maps to PLANNING (back-compat).
Step 4  Tier 3–4 — rewire discover.md / plan.md / po.md / director.md to the consult flow.
Step 5  Tier 5 — update canonical pipeline strings + menus.
Step 6  Tier 6 — deprecate the storm skill across adapters (only once consult flow ships).
        Run: pathly-setup claude --apply --repair ; python -m build
Step 7  Keep Tier 7 untouched (telemetry back-compat).
```

**Minimal viable removal = Steps 1–3.** That alone removes the skipped state from the
pipeline and the UI. Steps 4–6 are the consult-flow migration.

---

## 4. Back-compat shim (Step 3 detail)

When the FSM recovers state and reads `current = "STORMING"` from an old STATE.json or
event log, map it to `PLANNING` before proceeding. One guard in the recovery path
(`fsm_ops.py` / orchestrator recovery) prevents any in-flight feature from breaking.

```python
if state.get("current") == "STORMING":
    state["current"] = "PLANNING"   # STORMING removed 2026-06; consult flow replaces it
```
