# Learnings: build-proof

Things a fresh worker would otherwise waste time rediscovering: a command that works, a
trap, a quirk of the environment. Append one or two lines, newest last, tagged with your
ticket number. Never edit or delete another line. Keep it short; a human prunes it.
- (01) The conductor test-first check counts anything under `tests/` as a test file, so the regenerated `tests/**/INDEX.md` can ride in the test-only commit. The full Test command took 7m20s here (2389 passed); run it in the background and poll its log.
- (02) git refuses a 0-byte `GIT_INDEX_FILE` ("index file smaller than expected"): a private index for a repo with no index yet must be absent, not empty. `git diff` ends a `---`/`+++` name that holds a space with a TAB, and an added line `++ x` prints as `+++ x`, so read names only before a file's first `@@` (`floor._file_diffs` does).
- (02) Copy a private index with `shutil.copy2`, not `copyfile`: git trusts an entry's stat data only when it is older than the index file's mtime, so a fresh mtime hides a same-second, same-size edit. A clock-free test: `git config core.trustctime false`, then pin the file's and `.git/index`'s mtimes with `os.utime`.
- (02) git C-quotes a `---`/`+++` name holding `"`, `\` or a control character even with `core.quotepath=off` (the TAB that ends a name with a space then follows the closing quote); an inherited `GIT_LITERAL_PATHSPECS=1` turns `:(exclude)x` into a literal file name.
- (03) `claimed_at`/`completed_at` are `isoformat()` stamps (`+00:00`, no fraction when microseconds are 0) and event `ts` ends in `Z`: a SQL string compare misorders the same instant (`...00.25Z` sorts after `...00.250000+00:00`), so compare times parsed with `datetime.fromisoformat`.
- (03) An "old DB" for a migration test: take a fresh `get_db()`, `ALTER TABLE comms_messages DROP COLUMN <col>` (SQLite 3.35+; 3.45 here), then call `db.migrations._run_migrations(conn)`.
- (04) `eventlog._now()` stamps event `ts` in whole seconds, so a `since` from `isoformat()` must be cut to its second (`replace(microsecond=0)`) or an event appended later in that same second reads as earlier and is dropped.
- (04) Every `eventlog.append_event` queues a debounced (0.5 s) `EVENTS.jsonl` rewrite into the storage dir, so a git test that snapshots after an event was written can see that file appear or change; assert on exact `tree.changes` only before any event is appended.
- (08) `git status --porcelain` names a wholly untracked folder as one `dir/` line, and `fsm_ops`' `build_baseline.preexisting_dirty` stores it that way; pass `--untracked-files=all` to see files and treat a `dir/` baseline entry as a prefix. Since 08 the packaged `team`/`team-build` carry `scope_gate`, so `spawn_window.wants_windows` is true for them and every team spawn takes two snapshots.
- (08) In a default run the plan is uncommitted at BUILDING, so `build_baseline.preexisting_dirty` holds `pathly/` (or ` M` plan lines): a gate that subtracts preexisting paths never sees a plan edit, and a test fixture that commits the plan hides that. Build the baseline from real `git status` output with the plan untracked, and judge such paths against a tree taken before the first spawn.
- (09) Adding a name to `feedback_priority` in `team.flow.yaml` fails `tests/dag_goals/test_flow_decompose.py::test_team_and_test_flows_declare_feedback_priority` (it pins the exact list for `team` and `test`), which only a full `-x` run reaches. A preset `ts` survives `eventlog.append_event`, so a test can put a `STATE_TRANSITION` 30 s ahead (`%Y-%m-%dT%H:%M:%SZ`) to check a "since" cut.
- (10) To test a stage prompt end to end, `eventlog.write_state(storage, {"current": "BUILDING"}, flow)`, call `fsm_ops.next_action` (stamps `build_baseline`), claim a task, edit, then `fsm_ops.complete_stage`: its `agent_hint.instructions` is the REVIEWING prompt, behind a `PATHLY AGENT: team/review` header. `require_tasks_done` holds REVIEWING->TESTING until `complete_task` is called, and any test that builds a prompt takes about a second (the embedder's model download fails behind the proxy; the 403 traceback in the log is noise).
- (10) A diff context line that is a markdown code fence reads as an indented fence (the diff adds a leading space) and closes a three-backtick fence, so wrap a pasted diff in a fence longer than any backtick run in it. A git tree snapshot older than `gc.pruneExpire` makes `git diff <tree> <tree>` fail, so a reader of `review_base` needs a visible fallback.
- (11) `tests/fsm_flows/test_fix_routing.py::test_build_prompt_for_agent_builder_path_unchanged` pinned a builder prompt as byte-identical with and without `feedback_file`; only a full `-x` run reaches it. A test that needs a dependency result appends `{"type": "AGENT_DONE", "run_id": "sched-<id>#<n>", "summary": ...}` with `db.queries.fsm_events.append_event(conn, root, feature, event)`, and builds the prompt from `dict(SELECT * FROM comms_messages)` (its `depends_on` is a JSON string, as `get_ready_tasks` returns it).
- (12) A supervisor test can drive a REAL `start_run`/`resume_parked_run` thread with only `fhc.next_action`, `fhc.complete_stage` and `pathly_orchestrator.supervisor._run_stage_via_terminal` patched; wait on the `on_done` callback (an Event), not on `state.status`, so the thread's `finally` has run. A verify command that appends to a log file (`[sys.executable, "-c", ...]` as a JSON argv in `verify.build`) shows how often the smoke ran. Black rewraps a one-line-closing docstring whose last line is over 88 columns, so run `black` on a new docstring before the lint chain.
- (13) A golden snapshot moves only for text in `compose_skill(<skill>, "claude")`: a `planning/plan.md` edit moves `planning__plan.claude.md`, but `task-dag-post` is `requires: goal_id`-gated and absent there (compose with `build_adapter_caps("claude", goal_id="g1")` to see it). `checks_in` reads only lines that START with a fence, so a ```check shown mid-line inside a JSON string in a ```json fence is not a block.
- (15) `tree.blob` returns a blob id, `tree.read` the file text. `complete_stage` only follows `on_board_count` (REVIEWING->BUILDING with a ready task) when given a `goal_id`, and the pending task must carry it. `run_gates` raises on an unregistered gate type, so a test that patches `fsm_ops._load_flow` to add `floor_gate` must patch only around `next_action` (`monkeypatch.context()`).
- (05) A test that drives `drain.drain_frontier` over a `git init` project needs no patching: `state.project_root` is the repo, `state.storage_path` the goal dir, and a fake spawn that edits files and returns `{"outcome": "success"}` is enough (`tests/dag_goals/task_proof_support.py`); `get_ready_tasks` wants `task_status='pending'` set on a posted task. The wrapper takes two tree snapshots per task, so the 10 drain tests take about 12 s.
- (06) Since `floor_gate` is in the packaged team flows, a test that writes a role's plan file raw (`REVIEW.md`, `IMPLEMENTATION_PLAN.md`) and then calls `complete_stage` is blocked as a `plan-edit`; write it inside `review_packet_support._as(repo, flow, role, state, work)`, which records the `SPAWN_WINDOW` a headless run would.
- (06) To drive team-build to RETRO in a test: `_enter_building`, `_claim`, then `complete_stage` per state, writing `REVIEW.md` through a reviewer window and calling `complete_task` before REVIEWING->TESTING; each advance builds the next prompt (about a second), and `{"done": True}` comes back from RETRO->DONE.
- (07) `floor_gate` runs before `task_checks`, so a test that edits a task's live text trips `task-edit` (FLOOR_FAILURES.md) first: allow it with `set_floor_allow(conn, id, ["task-edit"])` to reach the task-check gate. A check that writes a log must write OUTSIDE the repo (`tmp_path`, not `repo`), or the untracked file trips `scope_gate`/`floor_gate`; `tests/fsm_flows/task_checks_support.py` has the helpers.
- (07) `monkeypatch.undo()` in a test also undoes the patches the autouse fixtures made through the same `monkeypatch` (the DB path), so later reads see an empty DB; patch inside `with monkeypatch.context() as patched:` instead. To count how often a gate reads the event log, wrap `pathly_orchestrator.eventlog.read_events` (the gates import it inside the function) and call `check_task_checks(GATE, storage, prev, next, board="feature", feature_scope="demo")` directly.
- (16) Only `copilot` and `antigravity` have `resume: null` in `core/adapters.yaml`; `codex` resumes (`--continue`), so a test of the no-resume (`degraded`) branch of `resolve_session` needs `copilot`. A `start_run` test can read the `SESSION` events from the `broadcast_fn(topic, payload)` it passes in.
