# Design System - cli-command-center

> Generated by designer · Stack: react (Electron renderer) · 2026-07-06

## Query
ASCII diagrams showing how the CLI Command Center feature should look in its compact panel form and its north-star expanded modal form.

## Design Constraints

- The primary user is a Studio operator watching live headless runs, queued engine work, and recent sessions without leaving the floating monitor.
- The current near-term surface is a compact `CliMonitorBar` panel with this order: FLOW controls, Code Intel, queue state, ACTIVE sessions, then RECENT sessions.
- The stack is React + Electron renderer + CSS Modules + Zustand, so the design must map to existing component boundaries rather than invent new view technology.
- Existing styling decisions are already dark, compact, and operator-focused: `Command Center` header, 320px floating panel, tokenized spacing, muted labels, and status accents for running, queued, paused, done, and error states.
- The active build contract is narrow: emphasize the FLOW label, slightly enlarge flow buttons, keep a single separator line, and align body spacing to shared tokens.

## Builder Notes

- Keep the compact panel as the authoritative near-term UI. The modal is a future expansion, not the current implementation target.
- Preserve the current section order from the live component tree: FLOW, Code Intel, queue, ACTIVE, RECENT.
- Make FLOW visually heavier than the supporting labels; ACTIVE and RECENT should stay secondary.
- Keep the visual language dense and operational rather than marketing-like: dark shell, muted chrome, small monospace-adjacent labels, and bright status accents.
- Reuse existing component seams: `CliMonitorBar`, `FlowControlBar`, `CodeIntelControl`, `SpawnQueuePanel`, session/history rows, and a future `cliCommandCenterOpen` modal shell.
