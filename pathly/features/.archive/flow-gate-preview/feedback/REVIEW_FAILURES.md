# Flow Gate Preview — REVIEW_FAILURES

Adversarial review of P1 (frontend gate) + P2 (backend transient `stage_overrides` channel).
Code-intelligence (Pathly `/code/query`) was used to bound blast radius before reading (see the
run summary). Every finding cites live code.

## Findings

- [SEVERITY med] studio/src/renderer/src/components/shared/FlowGatePreview/useFlowGateState.ts:56-62 (+ useFlowGateStages.ts:65-68) — A fail-soft compose STUB can be promoted to a verbatim override. When a stage's `composeSkillPrompt` returns null (bare-agent `agent_map`, or any server error — DESIGN R3), `stageOf(state).prompt` becomes the stub `# <role>\n_(the <skill> skill composes at spawn.)_` and `segments=[]`. If the user opens **Sections** on that stub stage and confirms, `applySections` sets `sectionsUsed[state]=true` (useFlowGateState.ts:51-54) and `buildOverrides()` sends the stub as that stage's override. `fsm_compose.build_prompt` then uses the stub verbatim as `agent_text` (skips compose), so the stage spawns with NO skill body and NO platform fragments — no `completion-report` ⇒ no `AGENT_DONE` ⇒ the run vanishes from RECENT and is unbilled. This is the exact failure the single-agent gate guards against: `AgentForm.confirmSend` gates the override on `sectionsUsed && skill && composedBody` (studio/.../SingleAgentButton/AgentForm.tsx:186); the flow gate has no `composedBody`/segments guard, so it is NOT parity-faithful here. Compounding it: with `segments=[]`, `headingLayers({})` is empty (FlowGatePreview.tsx:105), so the SkillSplitModal platform-fragment LOCK does not hold for a stub stage — the user can exclude everything. → Fix: in `buildOverrides` (or `applySections`), skip stages whose `stageOf(state)?.segments` is empty (compose failed) so a stub is never sent as an override; optionally disable the **Sections** button for a non-composed stage. (Server-side is defense-only: `_validate_stage_overrides` can't tell a stub from a real trim.)

- [SEVERITY low] src/pathly_orchestrator/fsm_compose.py:312 vs :370 — `stage_override` is tested with two different predicates. Line 312 gates the override body with `if stage_override and stage_override.strip():` (whitespace-only ⇒ treated as ABSENT ⇒ composes the skill). Line 370 gates `_apply_stage_selection` with `if not stage_override and (ability_ids or excluded_sections):` (whitespace-only ⇒ treated as PRESENT ⇒ SKIPS the persistent stage selection). So a whitespace-only `stage_override` would compose the skill but silently drop the stage's persistent `ability_ids`/`excluded_sections`. Not reachable via HTTP today (`_validate_stage_overrides` drops blanks at _runner_bp.py:53 and `next_action` passes `… or ""`), but `build_prompt` is a module-level function (code-graph: 3 callers) and two diverging tests on one variable are a latent bug. → Fix: make line 370 mirror line 312, e.g. `if not (stage_override and stage_override.strip()) and (ability_ids or excluded_sections):`.

- [SEVERITY low] src/pathly_orchestrator/http_server/blueprints/runner/_runner_bp.py:16,51,54 — Per-value cap slices by characters but is named/measured as bytes. `_MAX_STAGE_OVERRIDE_VALUE_BYTES = 64*1024` is applied as `text[:64*1024]` (a Python str slice = 64K CHARACTERS, line 51), while the total is summed as `len(text.encode("utf-8"))` (bytes, line 54). A single 64K-char value of multi-byte text can be ~256 KB, so one entry alone can reach the total cap. Harmless for correctness/security — the total BYTE cap (line 54-56) still hard-bounds the whole map to ≤256 KB, within the Windows PowerShell temp-script path (studio/CLAUDE.md) — but the naming misleads. → Fix: slice on encoded bytes, or rename the constant to `_CHARS`.

- [SEVERITY low] studio/src/renderer/src/components/shared/FlowGatePreview/useFlowGateState.ts:47-49 — Editable-banner pencil edits are silently dropped unless Sections is also used. `editText` updates `edited[state]` (banner shows the edit) but does NOT set `sectionsUsed[state]`, so `buildOverrides()` omits a pencil-only edit. This faithfully mirrors the single-agent contract (AgentForm.tsx:186 — "plain submit ⇒ server composes", which avoids shipping a fragment-less body), so it is NOT a regression. But the flow gate's `PromptBanner` is `editable` with a pencil toggle and an "Edit the prompt for this run…" placeholder (PromptPreview.tsx:128), inviting an edit that a reasonable user expects to apply. → Fix (optional): either mark a pencil-edited stage `sectionsUsed` (but then finding #1's stub guard must exist first), or make the banner read-only until Sections is opened, to remove the footgun.

## Note on parity (resolved, not a defect)

The `buildOverrides` "sectionsUsed only" gate correctly mirrors the single-agent semantics
(`AgentForm.confirmSend`, AgentForm.tsx:181-196) — a plain submit must leave composition to the
server so the platform fragments are never dropped. The one place the mirror is imperfect is the
fail-soft **stub** path (MED finding #1), where the single-agent guard's `composedBody` clause has
no flow-gate equivalent.
