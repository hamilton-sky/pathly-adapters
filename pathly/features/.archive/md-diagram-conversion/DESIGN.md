## Design System Output

### Pattern
- **Name:** Funnel (3-Step Conversion)
- **Conversion Focus:** Progressive disclosure — show only essential info per step; use progress indicators; multiple CTAs
- **CTA Placement:** Each step: mini-CTA. Final: main CTA
- **Color Strategy:** Step colors: 1 (Red/Problem), 2 (Orange/Process), 3 (Green/Solution). CTA: Brand color
- **Applied to Diagram flow:** Trigger button → generation loading state → diagram render/preview
- **Sections:** 1. Trigger button in toolbar, 2. Loading/progress indicator, 3. Rendered diagram output + sidecar actions

### Style
- **Name:** Micro-interactions
- **Mode Support:** Light ✓ Full | Dark ✓ Full
- **Keywords:** Small animations, gesture-based, tactile feedback, subtle animations, contextual interactions, responsive
- **Best For:** Mobile apps, touchscreen UIs, productivity tools, user-friendly, consumer apps, interactive components
- **Performance:** ⚡ Excellent | **Accessibility:** ✓ Good

> **Studio context:** Studio is already a dark-mode Electron app with OLED-optimized dark surfaces
> (`--bg-deep`, `--bg-elevated`, etc.). The Diagram action UI must integrate into the existing dark
> `MarkdownEditor` panel — do not introduce light-mode-only colors. Apply micro-interactions
> (button press scale, loading pulse, success flash) consistent with the existing Studio token palette.

### Typography
- **Heading:** Inter (already loaded via `@fontsource/geist` + `@fontsource/inter` in Studio)
- **Body:** Inter
- **Mood:** dark, cinematic, technical, precision, clean, premium, developer, professional, high-end utility
- **Best For:** Developer tools, fintech/trading, AI dashboards, streaming platforms, high-end productivity apps

### Key Effects

#### Micro-interactions for the Diagram action button
- **Idle:** standard toolbar button appearance matching existing MarkdownEditor header buttons
- **Hover:** subtle background highlight `150ms ease-out`; `cursor: pointer`
- **Press/Active:** scale `0.95 → 1.0` over `100ms`; no layout shift
- **Loading:** animated pulse or spinner; button disabled (`pointer-events: none`); loading text "Generating…"
- **Success:** brief green flash `200ms` → diagram pane appears with `opacity 0 → 1` transition `250ms ease-out`
- **Error:** red border flash `200ms`; toast notification with retry action

#### Diagram output pane
- Appears inline below the editor or in a split-pane; `opacity 0 → 1` at `250ms ease-out`
- Sidecar persistence badge (shows "saved" or "cached") at `100ms ease-out`
- Re-generate button with secondary styling (not CTA weight)

### Anti-patterns to avoid
- Complex onboarding (no tutorial overlays for the Diagram button — it must be self-evident)
- Slow performance (diagram generation is async — always show loading state >300ms)
- Emoji as icons — use SVG/Lucide icon for the Diagram toolbar button
- Horizontal scroll in the diagram output pane
- Fixed widths on the output pane container — use `width: 100%` / `flex: 1`

### UX Pattern Notes

#### Toolbar button (from UX search)
- **Loading state:** disable button during AI generation; show spinner + "Generating…" label
- **Active state:** highlight with `border-b-2` or background change to indicate diagram mode is on
- **Loading indicator:** `animate-pulse` skeleton or spinner for operations >300ms
- Button must be `disabled={loading}` to prevent double submission

#### Diagram output panel
- Use skeleton/shimmer placeholder while generation runs (>1s operations: `progressive-loading`)
- Empty state: show "No diagram yet — click Diagram to generate" with the toolbar button highlighted
- Error state: show message with cause + retry action (not just "Error occurred")
- Sidecar file saved indicator: subtle toast auto-dismissed in 3–5s

#### Dark mode (Studio-specific)
- Output surface: `background: var(--bg-elevated)` with `border: 1px solid var(--border-subtle)`
- Text on diagram surface: `color: var(--text-primary)` — verify 4.5:1 contrast
- Skeleton shimmer must be visible on dark background — use `rgba(255,255,255,0.06)` sweep
- No light-mode-only color assumptions — all states must work in Studio's dark theme

## Component Spec

### Diagram ActionPill — use the existing shared component

The Diagram pill is a **third instance of the shared `ActionPill` component**. No new toolbar
button component is needed. Example usage in `EditorHeader.tsx`:

```tsx
import { Network } from 'lucide-react'
import { LayoutTemplate } from 'lucide-react'
import ActionPill from '../shared/ActionPill/ActionPill'

<ActionPill
  state={diagramState}               // PillState: 'idle' | 'running' | 'busy' | 'done' | 'error'
  progress={diagramProgress}         // ActionProgress | null
  hasPath={!!activeFilePath}         // gates the run + gear
  title="Diagram"                    // idle label
  runningVerb="Diagramming"          // shown as "Diagramming…" while running
  mainIcon={<Network size={13} />}   // Lucide Network icon
  idleTip="Generate diagrams from this document"
  runningTip="Diagram generation in progress…"
  ariaName="Diagram"
  onRun={handleDiagramRun}
  onStop={handleDiagramStop}
  configTip="Diagram options"
  onToggleConfig={handleToggleDiagramConfig}
  resultIcon={<LayoutTemplate size={11} />}
  resultLabel="Gallery"
  resultReady={hasDiagramResult}
  resultTip="Open diagram gallery"
  onOpenResult={handleOpenDiagramGallery}
  tone="green"                       // result chip glows green when diagrams are ready
/>
```

**PillState transitions:**
- `idle` → click run → `running` (spinner, timer, "Diagramming…")
- `running` → success → `done` (green chip pulses, gallery button enabled)
- `running` → error → `error` (red border, error label)
- Stop button replaces gear while `running`; gear returns when stopped/done

### DiagramGallery panel
Location: `studio/src/renderer/src/components/MarkdownEditor/DiagramGallery/`

```
DiagramGallery/
  DiagramGallery.tsx
  DiagramGallery.module.css
```

- Opens when Gallery chip is clicked (`onOpenResult`)
- Renders each diagram as a card: Mermaid/PlantUML source → rendered SVG + copy/download actions
- Container: `width: 100%`, `min-width: 0` — responsive; verify at ≤200px wide
- Lightbox (zoom/pan): simple overlay at `z-index: 100` (or use `--z-modal` token); dismissible with Escape
- Empty state (no diagrams yet): "Click Diagram to generate" hint
- Skeleton shimmer during generation: CSS `@keyframes shimmer` on `var(--bg-surface1)` cards

### Sidecar file format (non-UI, for builder reference)
Diagram output is persisted alongside the `.md` source as `<filename>.diagram.json`:
```json
{
  "source_hash": "<md5 of source .md content>",
  "generated_at": "<ISO timestamp>",
  "diagram_type": "mermaid|plantuml|ascii",
  "content": "<diagram source string>"
}
```
The UI reads this sidecar on mount to pre-populate the gallery without re-generating.

### Mermaid rendering (from RESEARCH.md)
- Pin `mermaid` to **v11** (ESM compat + config-copy bug fixed)
- Load via dynamic import in a `useEffect`: `import('mermaid').then(m => m.default.render(...))`
- Keep singleton: call `mermaid.initialize()` once; reuse the module reference
- Set `securityLevel: 'loose'` only for trusted (user-authored) content
- Each render call needs a unique DOM `id` to avoid conflicts across gallery cards
