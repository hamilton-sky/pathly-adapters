# PO Notes — studio-sidebar-redesign
_Generated by PO advisor (auto-flow mode)_

## Problem & Users
The current studio sidebar forces users to manually toggle between WORKSPACE and LIBRARY tabs regardless of which main panel they are working in, creating friction and surfacing irrelevant content. Primary users are Pathly Studio developers who switch frequently between Monitor (file inspection) and Canvas (flow building) contexts; they need the sidebar to automatically present the right tools, and they need library items to be drag-and-drop-onto-canvas to build flows efficiently.

## MVP Scope

### Story 1: Context-aware sidebar driven by activePanel
**As a** Studio user
**I want** the sidebar to automatically show the relevant content for whichever main panel I am using
**So that** I do not waste clicks toggling tabs that show me the wrong thing

Acceptance criteria:
- When `activePanel === 'monitor'` (Zustand store), sidebar renders only Workspace content (file tree of Debugs, Explorations, Lessons, Pipeline-walkthrough).
- When `activePanel === 'flow'` (Canvas), sidebar renders only Library content (cards + My Library).
- No tab bar / WORKSPACE-LIBRARY toggle is visible in either context.
- A plain section header replaces the toggle and reflects the current context.
- Switching `activePanel` triggers a 150ms opacity + 4px y-translate transition between sidebar contexts.

### Story 2: Move plan folder list into Monitor panel body
**As a** Studio user inspecting a plan
**I want** plan progress rows to appear above the event log in the Monitor panel itself
**So that** the sidebar workspace stays focused on raw artifacts and the Monitor shows the run state in one place

Acceptance criteria:
- `PlanSection` is removed from `WorkspacePanel.tsx`.
- Monitor panel body renders plan progress rows at the top, above the existing event log.
- Sidebar workspace section now lists only: Debugs, Explorations, Lessons, Pipeline-walkthrough.

### Story 3: Library card grid with pill filter tabs
**As a** Canvas user assembling a flow
**I want** the library presented as a 2-column card grid with pill filter tabs
**So that** I can browse Flows/Skills/Agents/Templates visually rather than navigating a file tree

Acceptance criteria:
- `LibraryPanel.tsx` replaces the file-system tree with a 2-column card grid.
- Pill filter tabs: FLOWS | SKILLS | AGENTS | TEMPLATES.
- Each card uses the type-color accent (Flows=#00ff87, Skills=#ff9f43, Agents=#6c72ff, Templates=#ff6b9d).
- Card labels use monospace (JetBrains Mono); descriptions use sans-serif.
- Global library section uses #00ff87 (green) accent.

### Story 4: My Library compact chip row
**As a** Canvas user with my own saved items
**I want** my personal library shown as a compact horizontal scroll chip row below the global library
**So that** my items are visually distinct and accessible without dominating the sidebar

Acceptance criteria:
- "My Library" section appears below the global library section.
- Renders as a compact horizontal scroll chip row.
- Uses purple/violet accent #6c72ff to differentiate from the green #00ff87 global library.

### Story 5: Drag library items onto Canvas
**As a** Canvas user building a flow
**I want** to drag any library card or chip — including items nested inside a flow card — directly onto the canvas
**So that** I can build flows by dragging without leaving the sidebar

Acceptance criteria:
- All library cards (Flows, Skills, Agents, Templates) carry `draggable=true`.
- Items nested inside a Flow card are individually draggable.
- All chips in "My Library" carry `draggable=true`.
- Drag data payload includes: `type`, `id`, `name`.
- Cards and chips show `cursor: grab` styling on hover.
- A drag-handle affordance is visible on each draggable element.
- Existing canvas drop handlers receive the payload without modification.

### Story 6: Sidebar visual system tokens
**As a** Studio user
**I want** the redesigned sidebar to feel cohesive with the broader Studio dark theme
**So that** it reads as a polished part of the app rather than a bolted-on panel

Acceptance criteria:
- Sidebar background `#0d0d14`, width `280px`.
- CSS tokens for accents (`--accent-global: #00ff87`, `--accent-mine: #6c72ff`, and type colors) are defined in `Sidebar.module.css`.
- Monospace font (JetBrains Mono) applied to labels; sans applied to descriptions.

## Out of Scope
- Canvas drop handling logic (already implemented — only the drag source is new).
- Search / filtering inside the library card grid (filter pills only, no free-text search).
- Library item authoring or editing (browse + drag only).
- Persistence model changes for "My Library" (uses existing user storage).
- Resizable sidebar width (fixed at 280px).
- Collapsing the sidebar entirely.
- Keyboard navigation for cards / chips.
- Drag-and-drop reordering within My Library.
- Mobile / responsive layout.
- Light theme variants.
- Animations beyond the 150ms context-switch transition.

## Success Criteria
- A user switching from Monitor to Canvas sees the sidebar content change automatically within ~150ms, with no manual tab interaction.
- Zero references to `switchTab` or `libraryOpen` remain in `Sidebar.tsx`.
- `TabBar.tsx` is replaced by `SidebarHeader.tsx` (no toggle component remains in the sidebar shell).
- A user can drag a Flow, Skill, Agent, Template, item nested in a Flow, and a My Library chip onto the canvas; in each case the canvas receives a drop with `{type, id, name}` payload.
- Plan progress rows render above the Monitor event log; sidebar workspace no longer contains `PlanSection`.
- `npm run typecheck` (`tsc --noEmit -p studio/tsconfig.web.json`) passes after the change.

## Constraints
- **Technical**: React + Vite renderer (`studio/src/renderer/`); Zustand for `activePanel` state; existing canvas drop handler contract must be honored. TypeScript strict mode — run `node_modules/.bin/tsc --noEmit -p studio/tsconfig.web.json` from repo root.
- **Design tokens fixed**: background `#0d0d14`, sidebar width `280px`, accents (`#00ff87`, `#6c72ff`) and type colors (`#ff9f43`, `#ff6b9d`) are non-negotiable.
- **Font**: JetBrains Mono must be available (assume already loaded by Studio).
- **Files in play**:
  - `studio/src/renderer/src/components/sidebar/Sidebar.tsx`
  - `studio/src/renderer/src/components/sidebar/shell/TabBar.tsx` → renamed/replaced by `SidebarHeader.tsx`
  - `studio/src/renderer/src/components/sidebar/panels/WorkspacePanel.tsx`
  - `studio/src/renderer/src/components/sidebar/panels/LibraryPanel.tsx`
  - `studio/src/renderer/src/components/sidebar/Sidebar.module.css`
  - Monitor panel component (path to be confirmed by architect)
- **No commit to master without explicit user approval** (per repo policy).

## Edge Cases & Risks
- **`activePanel` set to an unexpected value** (neither `monitor` nor `flow`): sidebar must have a defined fallback — likely render Workspace and log a warning. Architect to confirm enum surface.
- **Rapid panel switching**: the 150ms transition should not stack or visually glitch if the user toggles quickly. Use a single transition class, not chained animations.
- **Drag started on a nested item inside a Flow card**: the drag must NOT also start a drag on the parent Flow card. Event propagation must be stopped at the nested item.
- **Empty states**: Library with no items for the selected pill filter, and My Library with zero chips, must render an empty-state placeholder rather than collapsing the section.
- **Long card titles**: cards in a 2-column grid at 280px sidebar width have limited horizontal room — titles must truncate gracefully (CSS ellipsis), not wrap unboundedly.
- **Plan progress rows in Monitor**: ensure they do not push the event log off-screen on short viewports; consider max-height or collapsibility (architect call).
- **Persistence regression**: removing `switchTab`/`libraryOpen` from the store may break other consumers — full repo search for those identifiers required before deletion.
- **Drag affordance discoverability**: with no tab bar and a new visual language, users may not realize cards are draggable. The drag-handle affordance is the discoverability mechanism — it must be visible by default, not only on hover.
