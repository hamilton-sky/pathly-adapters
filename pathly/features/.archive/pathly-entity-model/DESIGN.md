# Design System — pathly-entity-model

> Generated by UI UX Pro Max · Stack: react (Electron) · 2026-06-29

## Query
CardSidebar grouped navigation component for Pathly Command Center Studio — React (Electron app) — collapsible sections for Features, Goals, Lessons, Explorations with per-kind accent colors, empty groups hidden, collapsed rail shows per-kind dot clusters, data-kind attribute for theming

## Design System Output

### Product Profile
- **Type:** Productivity tool — developer orchestration dashboard
- **Style:** Flat / Minimal Dark — professional, data-dense, subdued chrome
- **Stack:** React + TypeScript (Electron renderer process)
- **Primary surface:** Sidebar navigation rail with collapsible grouped sections

### UX Rules Applied

| Rule | Decision |
|---|---|
| `nav-hierarchy` | Sidebar = secondary nav; per-kind grouping = predictable hierarchy |
| `empty-nav-state` | Empty groups are `hidden` (not rendered), not visible with "No items" |
| `nav-state-active` | Active item: kind-color text + 2px left border + semibold; no background color-only |
| `color-not-only` | Kind identified by icon + label + color; never color alone |
| `keyboard-nav` | `ChevronIcon` toggling via keyboard; `aria-expanded`; `aria-current="page"` on active |
| `focus-states` | 2px focus ring, offset 1px, color matches kind accent |
| `state-preservation` | Collapse/expand state persisted in localStorage per-kind |
| `adaptive-navigation` | Rail collapses to 48px icon mode at window < 900px; re-expands on drag or hover |
| `studio-responsiveness` | `min-width: 0` on flex children; no `overflow: hidden` near drop-up menus |

### Collapsed Rail — Dot Cluster Spec

When rail is collapsed (48px), each visible section shows a vertical stack of colored dots (one per item, up to 5, then `+N` ellipsis dot):

```css
.dot-cluster { display: flex; flex-direction: column; align-items: center; gap: 4px; }
.dot         { width: 6px; height: 6px; border-radius: 50%; background: var(--color-kind-*); opacity: 0.7; }
.dot.active  { opacity: 1; width: 8px; height: 8px; }
```

Tooltip on hover shows item label (native Electron `title` attribute; no JS tooltip needed).

### Anti-Patterns to Avoid

- Do NOT use `overflow: hidden` on the sidebar container — clips drop-up menus and focus rings
- Do NOT use `position: fixed` sidebar with no content inset — use CSS Grid `grid-template-columns`
- Do NOT convey kind by color alone — always pair with icon + label
- Do NOT mix filled and outline icons for the same hierarchy level
- Do NOT make board POST a hard dependency of sidebar rendering — degrade gracefully if `/comms` is unreachable

### Accessibility Checklist

- [ ] All section headers: `<button>` with `aria-expanded`
- [ ] Active item: `aria-current="page"`
- [ ] Icon-only collapsed rail: each button has `title` + `aria-label`
- [ ] Focus ring visible in both light/dark (2px, kind-color)
- [ ] Section groups: `role="list"` on `<ul>`, no nesting beyond one level
- [ ] Keyboard: Space/Enter toggles group; Tab navigates items; Escape closes focused group

### 1. The core model — `scope` vs `slug`

> **`scope` answers "which board tier." `slug` answers "where on disk." They are different
> things. Today the code conflates them by passing `topic = scope` into the FSM. That
> conflation IS the production bug, and separating the two IS the structural fix.**

Two distinct identities, currently collapsed into one variable:

| Axis | `scope` | `slug` |
|---|---|---|
| Question it answers | which **board addressing tier** | where on **disk** the artifacts live |
| Values | `feature` → `<slug>` · `project` → `<abs path>` · `global` → `'global'` | a bare slug: `md-diagram-conversion`, `goal-fix-loop-3f9a1c22` |
| Used as | board-message `scope` column / context retrieval key | FSM `topic` → `pathly/<domain>/<slug>/` storage dir |

**Why a feature works today and a project goal does not:**

```
FEATURE (scope == slug, self-binding):
  scope = "md-diagram-conversion"  ── used as topic ──►
  Path(root) / "pathly" / "md-diagram-conversion"   ✓ resolves correctly

PROJECT GOAL (scope is an absolute path):
  scope = "C:/Users/Yafit/pathly-adapters"  ── used as topic ──►
  Path(root) / "pathly" / "C:/Users/Yafit/pathly-adapters"
       │
       └─► pathlib DISCARDS left operands when the right is absolute
           ⇒ collapses to the PROJECT ROOT itself
           ⇒ PO_NOTES gate checks <root>/PO_NOTES.md ── never matches ──►
              PO_DISCUSSING re-spawns the PO forever  ✗ THE BUG
```

The fix: **slug — not scope — becomes the FSM topic.** Project/global goals get a real slug
directory under `pathly/goals/<slug>/`; the FSM resolves storage there; the `PO_NOTES` gate
matches; the consultation FSM advances. The join key linking a board row to its folder is a
new nullable **`comms_messages.slug` column with a `UNIQUE` index** — never folder-equals-path.

### Taxonomy — 4 kinds; slug is identity, scope is addressing

| kind | folder | board row (`comms_messages`) | scope tier | FSM topic |
|---|---|---|---|---|
| **feature** | `pathly/plans/<slug>/` | folder + `STATE.json` | `feature`, scope=`<slug>` | `<slug>` (correct today) |
| **goal** (project) | `pathly/goals/<slug>/` | `type='goal'`, executor∈{single,loop,team} | `project`, scope=`<abs path>` | `<slug>` (was the abs path → bug) |
| **goal** (global) | `pathly/goals/<slug>/` | `type='goal'` | `global`, scope=`'global'` | `<slug>` |
| **lesson** | `pathly/lessons/` (flat) | `type='discovery'` (💡) | `global`/`project` | none (never runs an FSM) |
| **exploration** | `pathly/explorations/<slug>/` | `type='discovery'` | `feature`, scope=`<slug>` | `<slug>` |

### Recommended structure — keep `plans/`, add `goals/`

Do **NOT** rename `pathly/plans/` → `pathly/features/` (PO_NOTES Out-of-Scope #1; pure blast
radius, zero behavioral gain). The dual root is already live and backward-compatible.

```
pathly/
  plans/<slug>/              UNCHANGED — features
  goals/<goal-slug>/         NEW — project/global goals get a real slug dir (fixes the bug)
  lessons/                   UNCHANGED — flat collection
  explorations/<slug>/       UNCHANGED
  debugs/<slug>/             UNCHANGED
  pipeline-walkthrough/      UNCHANGED
```

**Hard invariant:** every storage path is exactly `pathly/<domain>/<slug>/` (two components
under `pathly`). This keeps `_agent_done_watcher`'s `project_root = feature_dir.parent.parent.parent` correct.

### 2. Artifact contract — `## Design System Output` makes "wrote a file ⇒ it's on the board" STRUCTURAL

**(a) `core/skills/artifact-manifest.yaml`** — single source of truth for FSM gates:

```yaml
roles:
  po:             { file: PO_NOTES.md,                 gate: '#' }
  architect:      { file: ARCHITECTURE_PROPOSAL.md,    gate: '## ' }
  web-researcher: { file: RESEARCH.md,                 gate: '## ' }
  designer:       { file: DESIGN.md,                   gate: '## Design System Output' }
  planner:        { file: IMPLEMENTATION_PLAN.md,      gate: '## Phase' }
  reviewer:       { file: feedback/REVIEW_FAILURES.md, gate: '#' }
  tester:         { file: feedback/TEST_FAILURES.md,   gate: '#' }
  retro:          { file: RETRO.md,                    gate: '#' }
  explorer:       { file: CONCLUSIONS.md,              gate: '#' }
overrides:
  planner.planning/dag-sketch: { file: DAG_PLAN.md, gate: '## Tasks' }
```

**(b) `core/skills/fragments/artifact-register.md`** — fragment contract: (1) write the role's named artifact to `<out_path>`; (2) append to `<feature_path>/ARTIFACTS.jsonl` `{role, path, type, title, summary, ts}`; (3) advisory board POST (skip if down).

**(c) Deterministic reconciler** — FSM gate `stat`s `storage_path/<artifact>`; when first seen, `complete_stage` calls `db/queries/comms_artifacts.py:ensure_attached(slug, board, scope, artifact_path, role)` — an UPSERT keyed by `(scope, artifact_path)`. For non-FSM modes the supervisor's post-PTY path reads `ARTIFACTS.jsonl` and calls the same `ensure_attached`; fallback: resolve role from manifest → stat file → attach if present.

> **Overspray fix:** do NOT add `artifact-register` to `composition.yaml defaults:`. Attach per-skill to pipeline-role skills only. The manifest `roles:` map IS the allow-list.

### 5. The path-scope bug fix

**Three-part elimination:**

**A. `_safe_topic` fail-fast guard (ship FIRST):**
```python
def _safe_topic(topic: str) -> str:
    if (not topic or os.path.isabs(topic) or topic in (".", "..")
            or re.search(r'[\\/:]', topic) or '..' in Path(topic).parts):
        raise ValueError(f"unsafe FSM topic {topic!r}: must be a bare slug, not a path/scope")
```

## 8. Addendum — the planner DAG-seeding race (root cause + partial fix shipped)

A separate, independent failure from the path-scope bug: **the consultation flow's PLANNING stage runs but seeds no goal+task DAG, while the single-agent planner — same `planning/plan` skill, same prompt — does.** (Verified by a 7-agent investigation workflow; load-bearing facts re-checked by hand.)

**Root cause.** `planning/plan` wrote its `AGENT_DONE` completion report at the end of Phase 3 (`plan.md:86`), *before* Step 4 (writes `IMPLEMENTATION_PLAN.md`), Step 5 (verify), and **Step 6 (Post Tasks to Comms Board → seeds `type=goal` + `type=task`, `plan.md:273`)**. With `early_advance` on by default, the supervisor returns the instant that early `AGENT_DONE` lands, calls `complete_stage`, the `PLANNING→DONE` gate (`IMPLEMENTATION_PLAN.md` contains `## Phase`) fires, and the run ends — **while the planner is still mid-skill, before Step 6 runs.** The single-agent planner runs the identical skill but through `start_board_run` with **no FSM `complete_stage` gate**, so nothing acts on the early `AGENT_DONE`; the agent runs to its true end and Step 6 fires. The difference is purely the gate, not the prompt (`_decompose_directive` fires correctly: `response['agent']=='planning/plan'` and `goal_id` is set).

The "planner spawns before the designer tab closes / behaves differently" observation is the same root area: `early_advance` overlaps *every* transition by design, but it's conspicuous at PLANNING because that stage runs the long, multi-phase, subagent-spawning `planning/plan` while ARCHITECTING/RESEARCHING/DESIGNING run single-pass `team/*` skills.

**Fix A — SHIPPED (`plan.md`).** Moved the completion report to **Step 8** — the genuine final action, after Step 6 seeds the DAG. Early-advance can no longer fire before the DAG exists, in *any* flow (consultation and single-agent converge on one skill). Verified in the composed prompt: the `AGENT_DONE` trigger now follows the DAG-seed step. Also resolves the old self-contradiction where the summary's `N` ("files written in Step 4") was requested before Step 4 ran.

**Fix C — SHIPPED (`plan.md`).** Step 6's idempotency guard is now scoped to `?goal_id=$GOAL_ID` (was a feature-wide "any tasks → skip", which made a fresh decompose of a new goal silently seed nothing); and a server-unreachable miss must now be recorded in the Step 8 summary (`"… seeded 0 tasks — comms server unreachable"`) instead of skipping silently.

**Fix B — CONTRACT, not yet built.** The consultation `PLANNING→DONE` gate should assert the **deliverable** — that the DAG exists (a board task-count for `goal_id`) — not a filesystem stat of `IMPLEMENTATION_PLAN.md` containing `## Phase`. The planner's product is board state, so the gate should assert board state. This needs either a new FSM gate type (board task-count, alongside `on_content`/`on_state_counter`) or a Step-6 sentinel the gate keys on. This is the planner instance of §2's per-role artifact contract: the planner's "artifact" is the DAG, and the gate asserts the artifact exists.

**Invariant (new, general).** A stage skill's `AGENT_DONE`/completion report MUST be its **genuine last act**, after every artifact *and* board write. Audit the `team/*` skills for the same latent race — e.g. is `DESIGN.md`'s `## Design System Output` (the DESIGNING gate marker) written before `team/design`'s `AGENT_DONE`? If so it shares this class of bug, just less visible because the skill ends right after.

**Still required for project/global goals.** Fix A unblocks PLANNING for *feature* goals. Project/global goals still die in the PO loop (the path-scope collapse, §5) before reaching PLANNING — so the slug/scope split is the prerequisite for project-goal consultation to ever seed a DAG.
