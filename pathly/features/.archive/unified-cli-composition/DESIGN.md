## Builder Notes

- Reference this file when implementing UI components for this feature.
- Override any recommendation that conflicts with existing project design tokens.
- Stack: react - use stack-specific imports and patterns from the output above.
- Treat the generated "Hero + Features + CTA" pattern as non-applicable to this feature. This work belongs inside the existing Studio control surfaces, not a marketing layout.
- Keep the established Pathly interaction model: visible PTY tabs remain available, while the primary user feedback stays on the launching control via `ActionPill` and `RunPill`.
- Reuse existing Studio components and tones where possible. The design goal is convergence of Summary, Analyze, Split, Decompose, and goal-run feedback, not a new visual language.
- Prefer a restrained operator-tool palette over the suggested indigo-heavy system if the builder needs new tokens. Neutral panels, strong status contrast, and clear success/error differentiation matter more here than brand-forward accenting.
- Ignore the generator typography recommendation. Follow the repo's current Studio typography unless a local component already opts into a different display face.
- Preserve the rollout gates from the architect assessment: prove the compose seam and file-capture transform UX first, then decompose, then loop board I/O. The UI should make those boundaries legible rather than implying all execution modes behave identically.
