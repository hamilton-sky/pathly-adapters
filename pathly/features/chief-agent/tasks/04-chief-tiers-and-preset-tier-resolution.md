# Define the chief tiers and resolve a preset to its tier

Type: task
Status: resolved
Blocked by: —
Test first: yes

Add `src/pathly_orchestrator/supervisor/chief_tiers.py`, the one place that says what a chief may
do. It is code, never data read from prompt text.

- `ACTIONS = ("read", "post", "plan", "decide", "run", "stop", "answer")`.
- `TIERS`: `status` → `read`; `planner` → `read`, `post`, `plan`; `operator` → all seven.
- `actions_for(tier) -> frozenset[str]`: the tier's actions; an unknown tier gets `status`'s.
- `normalise_tier(value) -> str`: lower-cased and stripped; anything not in `TIERS` is `status`.
- `resolve_preset_tier(preset, project_root) -> str`: if a user prompt file `chief/<preset>`
  exists (look it up with `skills/prompt_files.read_prompt_file`, which already merges project over
  global), its leading front matter's `tier:` value decides through `normalise_tier`, and a file
  with no front matter or no `tier:` is `status`; otherwise the built-in names `status`, `planner`
  and `operator` map to themselves; anything else is `status`. A malformed preset name (anything
  `read_prompt_file` rejects) is `status`.
- `strip_front_matter(text) -> str`: the text with one leading front-matter block removed; reuse
  `skills/compose_base._strip_leading_frontmatter` rather than a second regex.

Parse only a leading `---` block and only its `tier:` line; ignore every other key. This is the
brief's `Decided:` line: each preset names its base style, preset text never grants permissions,
and an unknown or missing style means Status (read-only).

**Decisions**

- Built-in names match exactly (`preset in TIERS`), with no lower-casing or stripping of the preset
  name. `read_prompt_file`'s `_ID_RE` ends in `$`, which also matches before a trailing newline, so
  `chief/operator\n` passes the id check, finds no file and, with an exact match, falls to `status`;
  a lenient match would have made it `operator`. The cost: a client that sends `Operator` gets
  `status`. A wrong guess fails read-only.
- `actions_for` is strict too: an unknown tier, `"Planner"` included, gets `status`'s actions. The
  tier bound to a session is whatever `resolve_preset_tier` returned, which is already normalised.
- Only an unindented `tier:` line of the leading block counts (first one wins); the value goes
  through `normalise_tier` as is, so a quoted value (`tier: "planner"`) or one with a trailing
  comment is `status`. The block is the exact text `strip_front_matter` removes, so what is pasted
  and what was read for the tier cannot disagree.
- `TIERS` is a `MappingProxyType` rather than a plain dict, so no caller can edit a tier in place;
  `TIERS[...]` and `in` work as for a dict.
- Imports of `skills.prompt_files` and `skills.compose_base` are at module top: the `skills`
  package imports nothing from the orchestrator layers, so there is no cycle, and `lint-imports`
  keeps the layer contract.
- A file that exists for a built-in name decides alone: `chief/operator.md` with no `tier:` is
  `status`, and `chief/status.md` with `tier: operator` is `operator`. This follows the ticket
  literally ("a file with no front matter or no `tier:` is `status`"); it means saving an edited
  Operator preset without `tier:` downgrades it, until round two's "Save current as prompt" writes
  `tier:`.

**For later tickets**

- 06 and 08 import `resolve_preset_tier`, `strip_front_matter` and `actions_for` from
  `pathly_orchestrator.supervisor.chief_tiers`. `TIERS` is a read-only mapping; use `actions_for`,
  which never raises on an unknown tier.
- A tier stored on a session should be the string `resolve_preset_tier` returned (always one of the
  three names). Do not run `normalise_tier` on user input to pick a tier for a new session; resolve
  through the preset.
- `resolve_preset_tier` reads the prompt files on each call (no cache), so an edit to a preset's
  `tier:` takes effect on the next open, not for a session already open.
- Ticket 07's living-doc line asks for "the new files in the package tree": `chief_tiers.py` is
  already listed under `supervisor/` in `src/pathly_orchestrator/CLAUDE.md`, so 07 only adds its own.
