# Learnings: chief-agent

Things a fresh worker would otherwise waste time rediscovering: a command that works, a
trap, a quirk of the environment. Append one or two lines, newest last, tagged with your
ticket number. Never edit or delete another line. Keep it short; a human prunes it.

- (01) Lint chain from `commands.md` takes about a minute; piping it through `tail` hides its exit code, so read `${PIPESTATUS[0]}` or run it unpiped. The Test command takes about 5 minutes here: run it in the background and wait on its log.
- (01) `gen_test_index.py` rewrites `tests/INDEX.md` and `tests/<domain>/INDEX.md` when a test file is added, so a "test-only" commit leaves those two files for the final commit, and `gen_test_index.py --check` in Lint fails until they are committed.
- (02) Flask's test client serves a request on the test's own thread, so a route and the test share one thread-local `get_db()` connection: a per-connection pragma or open transaction a route leaves behind is visible to the test (and to the next test step) directly.
- (02) `python3.11`, `python3.12` and `python3.13` all exist in `/usr/bin` here, but only the venv's 3.12 has the project deps; to check a stdlib behaviour on all three, run a tiny script with `python3.NN -I script.py` (no pytest).
- (03) `black` reflows a long tuple in a moved/edited function and can push a file one line past 400 after the edit looks fine: run `black` before judging the size, then use the ticket's split fallback.
- (03) The floor guard flags any added `# noqa` (also on a re-export line copied from its neighbour) and reads only the committed diff `base..HEAD`: run `python3 scripts/floor-guard.py chief-agent NN <base>` after committing, not before. The repo has no flake8 or ruff step, so a re-export needs no `noqa`.
- (04) `skills/prompt_files.py::_ID_RE` ends in `$`, which also matches before a trailing newline, so `read_prompt_file("chief/x\n")` passes the id check (and then finds no file because the row id compare is exact): match names exactly after it, never `strip()` them.
- (04) The `skills` package imports nothing from the orchestrator layers, so `supervisor/` modules can import `skills.*` at module top without a cycle (existing ones import lazily by habit); the autouse conftest fixture patches `Path.home()` to `tmp_path`, so `write_prompt_file(..., scope="global")` in a test lands in a temp dir.
- (05) `bandit -q -r src/pathly_orchestrator/db -ll` prints dozens of "nosec encountered" / "Test in comment" warnings for old files and still exits 0: read the exit code, not the noise. A `black` run over `src/pathly_orchestrator/db` and the new test before judging is enough (no reformat was needed on the new code).
- (05) `get_db()` connections use `sqlite3.Row`, and the existing `run_tokens` row-to-dict idiom is `dict(zip([d[0] for d in cur.description], tuple(row)))`; `record_citation`-style code that catches `sqlite3.IntegrityError` should put the `try` outside `with _get_write_lock(conn)` so the guard rolls the connection back.
- (06) The installed claude is 2.1.302, not 2.1.292. With `-p` it still fires the `--settings` UserPromptSubmit hook under `--restricted` (hook stdin `session_id` is the `--session-id`), and `--output-format stream-json --verbose` shows `tools` = Bash, Glob, Grep, Read and `mcp_servers` = [] with `--strict-mcp-config` and `{"mcpServers": {}}`; about $0.002 on `--model haiku`. An interactive tab could not be tried here.
- (06) `close_chief` sets `closed_at` first and drops the run last, so a test that sees `closed_at` can still see the run: wait on `get_run(run_id) is None`. A chief a test leaves open keeps a watcher for `start_timeout`; `test_chief_session.py` closes them in an autouse fixture, because later the patched home is gone and the watcher would touch the real `~/.pathly`.
- (07) A route test fakes the spawn host by replacing `pathly_orchestrator.http_server.sse._broadcast_runner` (routes import it inside the function, so the patched name is the one used). A `../x` run id only escapes `_chief_root()` when that folder exists, so a traversal test must `mkdir` it first or the mutation passes unseen.
- (07) `app.main()` can be tested in a subprocess (about 0.5 s): `python -c` with `PYTHONPATH=<src>`, `HOME` and `USERPROFILE` set to a temp dir, `runner.embeddings.warm` and `app.app.run` replaced in the script; in the test process it would reset the root logger and the middleware globals.
- (08) A test-client call to an `/events/*` route blocks on the stream's first chunk, so a refusal test hangs instead of failing when the gate is missing; `test_chief_gate.py` swaps every `/events/*` entry of `app.view_functions` for a stub (autouse, `monkeypatch.setitem`). A test that fires every unlisted route also patches `os._exit`, which `POST /shutdown` calls on a timer.
- (08) `test_comms_write_perm.py::test_comms_write_perm_project_writers_constant` pins `_PROJECT_WRITERS` as an exact set: adding a project writer means adding it to `expected` there (and to `_DEFAULT_WRITE_PERMISSIONS["project"]`, which the same file checks against `allowed_roles`). A scripted mutation loop (edit one string, run `pytest -x`, restore in `finally`) checks 12 mutations of the gate in about 5 minutes.
- (08) To look at a body a route reads with `get_json`, use `request.get_json(silent=True, force=True, cache=False)`: without `cache=False` the forced parse is cached and a route that ignores a non-JSON content type then reads the dict. `read_json_body` (UTF-8, then cp1252) shows `{}` for a BOM, UTF-16 or UTF-32 body, which only `get_json` (raw bytes to `json.loads`) understands.
- (08) `uvx` on PATH makes `/code/query` resolve to the lsp backend in a test, and a query that gets past the role gate then starts a Serena session: patch `pathly_orchestrator.runner.code_context._resolve_backend` to return `"none"` (the gate tests do, in an autouse fixture).
- (08) A clean red run for a new module needs the module absent: the first red run overlapped with creating `chief_fields.py`, so move the file aside (`mv`), run the new tests, and restore it. A route table walked against `app.url_map` (`ROUTE_FIELDS` vs the routes) finds what a hand-picked case list misses; read each reachable view's source for `request.args`, `get_json` and `.get(` before filling the table, because `scope or feature`, a query-versus-body source and a fall back to the server's directory each hid a hole.
- (08) `black` reflows long lines the mutation harness searches for: write the mutation scripts against the black-formatted text and run black before the mutation loop, and let the script restore each file in a `finally` (check `git status` after). `pytest -n` is not available here (no xdist); `until grep -q '^exit ' out.txt; do sleep 5; done` waits for a backgrounded run.
- (08) To split a big test module, move AST nodes by name with a script (spans from the previous node's end so comments and decorators travel), put what several files use in one `*_support.py` next to them (imported by bare name: `tests/conftest.py` puts `tests/` on `sys.path`), import every autouse fixture and the fixtures they ask for (`app`) into each file, and prove it with `ast.dump` equality per definition plus a sorted `--collect-only` node-id diff; no `__init__.py` means basenames must stay unique across `tests/`.
- (08) A path-like `feature` or `scope` (`../x`, `a/b`) given to a route that joins it under the project makes the board mirror write `<scope>/pathly/project/BOARD.json` into the working directory in a test run: check `git status` for stray folders (`sub/`, `x/`) after a red run and remove them. `/comms/run` of an `evaluator` saves a reply with no artifact to `<root>/pathly/features/<scope>/artifacts/`, so its scope is a folder name too.
- (08) The global board mirror lives in `~/.pathly/global/BOARD.json`, and `tests/conftest.py` points `Path.home()` at `tmp_path`, so an assertion that a test "wrote no BOARD.json" must skip `.pathly` (`[p for p in root.rglob("BOARD.json") if ".pathly" not in p.parts]`) or it fails on correct code. The flusher thread writes after the request returns: a test that checks files on disk drains it with `board_mirror.flush_dirty(get_db())`, waits `DEBOUNCE_SECONDS + 0.3`, and drains again.
- (08) `board_mirror.board_from_scope` used to call any scope with a `/` a project root, whatever board the row was posted to, so a gate that binds by the DECLARED board lets a path scope on a feature or global board plant `<scope>/pathly/project/BOARD.json` anywhere: bind by the shape of the scope, and check the shape at the sink too (`scope_names.is_segment` / `is_project_root`). A goal's `slug` is stored from `POST /comms/post` as given and later joined into `goals/<slug>`: a stored string that reaches a path needs a check where it is joined, not only where it is posted. A mutation run found a rule whose tests still passed because another rule refused the same input with a different message: assert the refusal text, and that the legitimate spelling passes.
- (08) `sys.addaudithook` cannot be removed once added, so install it once and make it inert unless an `Audit` object is active; it sees `open`, `os.mkdir`/`rename`/`remove`/`rmdir`, `os.listdir`/`scandir`, `shutil` copies, `glob`, `sqlite3.connect` and a child process's `cwd`, but NOT `os.stat`/`os.path.exists`, so a clean audit says nothing about a probe. Prove an audit can fail before trusting it: one call per kind in each zone, a write a request makes through a caller the gate does not see, and the run failing once each guard is removed (project rules off: 229 touches; containment off: 35). A post indexes its artifact on a background thread and the board and event mirrors flush on a timer, so call `settle()`, drain both mirrors and sleep past the debounce before reading violations, and clear seeding writes after a short sleep or a late one is counted against the chief.
- (08) A key allowlist needs both halves: a static AST walk of the views and their helpers (find a key by what a name is bound to, such as `request.get_json()`, `read_json_body()`, `request.args` or a helper parameter called `body`; read `.get("k")`, `.getlist("k")`, `["k"]` and `"k" in …`) and a dynamic run that sends hostile values to every listed key. The walk misses a function outside the scanned package that is handed the whole body; the run misses a route whose baseline request never gets past the first check, so list the baselines and assert they are accepted. A `pytest.skip(` added to a test is a skipped test to the floor scan (`proof/floor.py`): call `symlink_to` bare as the repo's other tests do.
- (08) On POSIX a backslash is an ordinary file-name character, so a gate that turns `\` into `/` before it compares says two different directories are one: `/work/proj\` is a sibling folder and `\work\proj` a path under the server's cwd. Decide it once per host (`scope_names.host_is_windows()`, patched in tests with `raising=False` so a red run fails for the behaviour and not for a missing switch) and assert the property, that two strings with one spelling are one directory to `os.path.samefile`. The audit hook records the test's own `iterdir`/`rglob` too: delete those touches from `audit.violations` after a listing, or the clean run fails.
- (08) A fix that makes an audit reach a sink shows the next sink: the canned `cli` code backend (`codebase-memory-mcp` answers from a table, `shutil.which` and `CliProvider._run` patched) made `/code/query` open `CliProvider._file_hash`'s relative target under the server's cwd, which the earlier `backend none` baseline never reached. List what a baseline stops short of (`reroute`, `retry`, the codeintel/lsp/both backends) in the doc instead of calling the run complete.
- (08) A cache or a lookup keyed by a relative path or a bare name needs the project in the key: the same string is a different file in every project that holds the same bytes, and a directory has the hash `""` everywhere. Grep for `dict[tuple[` next to a `project_root` parameter; `/code/query` had two (`query._QUERY_CACHE`, `code_context_cli._CLI_CACHE`). An older test whose target did not exist relied on the `""`-hash cache entry (`test_null_result_not_cached`): give it a real file in `tmp_path` instead of weakening it. `LIKE '%/' || ?` needs the bound name escaped in Python (`%`, `_`, `\`) and `ESCAPE '\\'` in one static literal; the f-string with a module constant already carries a `# nosec`, so add none.
- (08) Judge a symlink on the path as written: `os.path.realpath("proj/link/../x")` takes `..` from the link's target, while `posixpath.normpath` collapses it first and lands inside the project. `hydrate_helpers.inside_root` resolves both sides, so a symlinked project root still works. A test that patches `host_is_windows` on a POSIX machine fails a realpath check on a backslash path unless the value goes through `scope_names.host_path` first. `symlink_to` works bare under `tmp_path` here, and `tests/` has no `__init__.py` so a new test's basename must be unique.
- (09) Cross-session messages, measured on claude 2.1.304 (receiver = `claude -p --input-format stream-json` kept open or a pty-driven interactive tab, sender = a second `claude -p --allowedTools "SendMessage ListAgents"`, hook = a script appending its stdin; scratch dirs, about $0.01 on haiku): the hook's `prompt` for such a message is `<cross-session-message from="uds:/tmp/cc-socks/<pid>.sock" from-name="<name>" from-mode="prompting">\n<text>\n</cross-session-message>`, no hook-input field differs (keys: session_id, transcript_path, cwd, scratchpad_dir, prompt_id, permission_mode, hook_event_name, prompt, session_title) and a typed prompt is bare. With `--restricted` the session binds no inbox (`--debug-file` shows `[uds-messaging] Skipped: restricted session`, no `messagingSocketPath` in `~/.claude/sessions/<pid>.json`): ListAgents omits it and SendMessage to its would-be `uds:` path fails ENOENT, so nothing reached the restricted hook; only the typed prompt did.

- (09) `black` grew a dense 400-line test file to 640 lines, over the limit: write tests in black's shape and put fixtures/helpers in a `*_support.py` beside them (imported by bare name; the test files import the fixtures by name, no `noqa`). A real-process hook test works: `werkzeug.serving.make_server("127.0.0.1", 0, app, threaded=True)` on a thread (its requests share the patched DB), the command from the session's `settings.json` through `shlex.split`, `PYTHONPATH=SRC` and `HOME` = `tmp_path` in the child's env.

Run `scripts/floor-guard.py` with `FLOW_DIR=pathly/features FLOW_TICKETS=tasks`; a throwaway `git worktree add --detach <dir> <test-commit>` plus `PYTHONPATH=<dir>/src` shows the test-only commit red without touching the working tree.
