## 0. Bottom line

**The concept executes, and it's now demonstrable on a real project.** The user's `invoice-tracker`
is a live worked example: a **project board decomposed into 3 feature boards** (`data-layer`,
`query-export`, `cli-tests`), each with a generated `SPEC.md` and goals, and **real
dependency-ordered DAGs** — `data-layer` ran a **5-task diamond DAG to completion** under the
`single` executor; `query-export` is a 7-task `team` run partway through.

Since 07-07 the assessment's **#1 blocker — in-app cost telemetry — is RESOLVED**, and three other
"open" items have closed (evaluator wiring, feedback-loop cap, whole-run crash-resilience). The gap
to production is unchanged in *shape* and is all finishing work, not rewrites:
**unhappy paths · honest scope (serial-not-parallel, no standalone drain) · distribution (unsigned
installer) · drift-gates (CI) that keep regressing.**

Verdict unchanged: **usable for supervised self-use; not yet a public/unattended product.** But the
distance is now measured in reliability cycles, not missing features.

## 2. Still OPEN (the real path to production)

**Reliability / scope**
- **Parallelism is serial-only inside a goal's DAG.** `_run_loop` hardcodes `SerialIsolation()`
  (`goal_executor.py:377`, `max_concurrency=1`). `LaneIsolation` (true parallel) exists but is
  **wired into no production executor — tests only**; `WorktreeIsolation` is `NotImplementedError("P3")`.
  Coarse cross-*feature* overlap exists via `file_claims`. Honest scope for v1 — confirm the
  demo/narrative doesn't imply within-DAG parallelism.
- **No standalone / CI drain.** The supervisor spawns via `TERMINAL_SPAWN` SSE
  (`supervisor/terminal.py:405`) → it **needs Studio as the PTY host**. `runner/invoke.py` is used
  only by the separate `runner/cli.py`, not the supervisor. "Headless" = no human in the per-step
  loop, **not** unattended/serverless.
- **Renderer is a required link.** `backgroundThrottling:false` is set (`index.ts:149`,
  `board.ts:44`), but full persist+rehydrate on a hard reload is deferred → a screensaver/reload
  mid-run can still orphan the flow. (SSE `/events/history` catch-up exists; full replay does not.)
- **Empirical cost-in-app proof still pending.** The *wiring* that broke B1 is gone and the gate
  path is env-independent (verified in code), but nobody has driven a live Studio run and watched a
  real number render in DB Explorer. This is the one remaining empirical milestone.

**Observability / accuracy**
- **"Full OpenTelemetry" overstates it.** OTLP-shaped spans are stored in the DB (Traces tab), but
  the wire exporter `otel_export.py` **no-ops unless `PATHLY_OTEL_ENDPOINT` is set** — nothing leaves
  the box by default.
- **Non-claude cost is estimated, not reported.** claude → real `total_cost_usd`; codex → priced
  from tokens (`cost_source="estimated"`, and the token-field shape is defensively parsed /
  unconfirmed against live output); agy/antigravity → char-heuristic or `"unavailable"`.

**Drift gates (SPEC's P1, still not landed)**
- **400-line SOLID rule regressed further: 14 files >400** in `src/pathly_orchestrator` (was 6) —
  `terminal.py` 610, `goal_executor.py` 530, `engine_actions.py` 482, `fsm_compose.py` 476, … — and
  there is still **no CI gate** for it, nor for doc-structure or dash-safety (3 hand-synced mirrors)
  or adapter-`_meta` parity.

**Distribution**
- **Installer signing is plumbed but not provisioned.** `electron-builder.yml` reads
  `WIN_CSC_LINK` / `MAC_CSC_LINK` / `APPLE_ID` from GitHub secrets, but until real certs are supplied
  every first-run user hits "Unknown Publisher." #1 gate for a public desktop release; pure ops.

**UX exposure gaps (features exist but aren't reachable)**
- **Feedback-routing control is half-exposed.** Basic tag→role routing is editable in the FlowWizard
  (`Step6FeedbackRouting`), but the just-shipped `feedback_priority` + `escalation_routing` are
  **YAML-only** (no UI), and the wizard's default routes are **pre-smart-fix** (omit
  `REQUIREMENT_GAP`/`PLAN_FEEDBACK`/`DESIGN_FEEDBACK`). Wizard save also writes to user-home, bypassing
  the `/flows/new` DB path.
- **A newly-created custom skill can't be fragment-mapped in-panel** — the composition panel is
  manifest-scoped; a brand-new skill isn't in `composition.yaml` (not editable in-panel), so it's
  delivered raw or with the `board_defaults` bundle only.
- **Core skill/agent edits still need `pathly-setup --repair`** to reach installed/runtime files —
  per-project fragment overrides are DB-live, but body edits to core are not auto-installed.
- **Board-scope leak** (diagnosed, not fixed): `evaluate` / `board_run` can post artifacts onto a
  repo-basename board instead of the feature/goal board.
- **`features.py` 'full' tier is semantically off** — rigor=`full` routes to `planning/plan` (ONE
  goal's DAG), not sibling goals; only `light` + `consultation` produce the goal set.

## 3. The 6-capability MVP — scorecard

The user's definition of a "proven system." Status verified this session:

| # | Capability | Status | Note |
|---|---|---|---|
| 1 | Multiple feature boards, each with a spec | **BUILT** | Live: invoice-tracker project → 3 feature boards + SPECs |
| 2 | Per-board goals with DAG tasks | **BUILT** | Live: real DAGs incl. a diamond; `/comms/goals` rollup |
| 3 | Implement DAG via executors + board-context + code-query (fragments) | **BUILT** | 3 executors drain DAGs; fragments inject board context + `/code/query`. **Serial-only.** |
| 4 | Trace CLI agents + full telemetry (OTel-like) | **BUILT** | Billing/tokens/spans + Studio surfaces. **OTel export dormant; non-claude cost estimated; live proof pending.** |
| 5 | Create flows + control feedback routing | **PARTIAL** | Engine live; **priority/escalation YAML-only; wizard defaults stale** |
| 6 | Create agents/skills + see fragment composition | **BUILT** | See+edit works; **new custom skills not fragment-mappable in-panel** |

**Net: 4 BUILT, 1 BUILT-with-caveats (telemetry), 1 PARTIAL.** The MVP is functionally present; the
work is reliability + closing the two exposure gaps (routing UI, custom-skill composition).

## 4. What to check next (the unhappy paths — you've only proven the happy path)

Ordered by risk:

1. **Failure & recovery** — kill an agent mid-task (non-zero exit): DAG marks `failed`, cascade-blocks
   dependents, run *terminates* (not hangs)? Force a review to fail 3×: escalation fires
   (`MAX_FEEDBACK_ROUNDS`) rather than looping? Abort mid-run: PTY dies, pill clears, **no orphaned
   CLI process** (Windows `killPtyTree`)? Kill + restart the FSM server mid-run: does it resume from
   the event log (`reclaim_stale_claims`)?
2. **Renderer-reload survival** — lock the screen / reload Studio mid-run: does the run survive or
   orphan? (The one reliability gap most likely to bite you daily.)
3. **Cost-in-app (empirical)** — drive one full Studio run and confirm DB Explorer shows a **real
   number**, not `$…`. This is the outstanding proof for the B1 fix.
4. **Multi-adapter** — run a stage on codex and antigravity headless; confirm copilot rejects with a
   clear message, not a silent hang.
5. **Clean machine + Windows** — fresh `pip install` → `pathly-setup` → Studio → one full run with
   nothing pre-warmed; confirm no orphaned engine processes after quit.
6. **Scale** — a 15–20-task DAG + a long single-agent run: board-retrieval relevance as the board
   grows; spawn dual-cap (global ≤8 / headless ≤5) queues without deadlock.
