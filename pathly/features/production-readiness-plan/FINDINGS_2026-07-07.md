## 0. Bottom line

The June assessment's entire verdict rested on P0-1 (*"the defining feature is broken — every run dies
after one stage"*). **That is no longer true.** Empirically (operator-confirmed this session): a
**consultation team ran, a loop agent ran, and a team-build flow ran** — all to completion. The
execution core works on the happy path.

The gap to production is now **the unhappy paths** (failure / abort / resume), **honest scope**
(serial-not-parallel; in-app cost telemetry off), and **distribution** (installer signing). None are
architecture rewrites — they are the finishing work the SPEC already lists.

**Worth:** the concept was always strong (board-as-substrate + passive FSM + fragment/skill split +
adapter-agnostic). What changed is that the concept now *executes*. The moat is execution/integration,
not structural — convergence-vulnerable vs. Agent HQ / Conductor / Vibe Kanban — so it lives on
reliability + the local-first / Windows / vendor-neutral seam. Worth finishing; **not** yet worth a
broad public launch.

## 3. What else to CHECK (you tested only the happy path)

Ordered by risk. You proved 3 executors succeed; production is defined by the paths below.

1. **Failure & recovery:** kill an agent mid-task / non-zero exit → does the DAG mark `failed`, cascade
   `blocked`, and the run *terminate* (not hang)? Force a review to fail 3× → does escalation fire or
   loop forever? Abort mid-run → PTY dies, pill clears, **no orphaned CLI process**? Kill + restart the
   FSM server mid-run → does it resume from the event log?
2. **Parallelism reality-check:** confirm you are OK with serial DAG drain for v1.
3. **Cost visibility:** during your runs did COST show a real number or `$…`? (B1 above.)
4. **Multi-adapter:** run a stage on codex and antigravity headless; confirm copilot rejects with a
   clear message, not a silent hang.
5. **Clean machine + Windows:** fresh `pip install` → `pathly-setup` → Studio → one full run with
   nothing pre-warmed; on Windows confirm no orphaned engine processes after quit (`killPtyTree`).
6. **Scale:** a 15–20-task DAG + a long single-agent run — board-retrieval relevance as the board
   grows; spawn scheduler dual-cap (global ≤8 / headless ≤5) queues without deadlock.

## 4. Shortest path to "usable app" (unchanged from SPEC intent, re-sequenced to today)

1. Export `PATHLY_PROJECT_ROOT` from Studio spawn env → cost telemetry turns on (B1).
2. Record one full Studio-open run with cost showing (the milestone).
3. Wire `evaluator` `_meta` across 4 adapters + parity test (T7).
4. Add a `max_iterations` guard to the feedback loop; verify abort/resume/failure paths.
5. Installer signing (Windows EV + Apple notarization) before any broad push.
6. Then the CI gates (400-line, doc-structure, dash-safety) so consolidation does not regress.
